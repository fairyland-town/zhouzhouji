# 周周记（校园活动周历）

把老师、学院、学校发布的**讲座 / 会议 / 宣讲会**通知，自动提取成 **活动名称、时间、地点**，并按周自动归类显示。
打卡、待办、记账、账户对账都收在同一个「记录」页里 —— **一周一记，生活更清晰。**

**纯本地运行 · 不联网 · 不调用任何收费 API · 不使用大模型 · 不消耗 Token。**

## 一之二、装到安卓手机上（推荐这条路）

**两步搞定，不需要装任何开发工具：**

```bash
npm run serve
```

终端会打印一个形如 `http://10.107.110.53:8080` 的**局域网地址**。
手机连上同一个 Wi-Fi，用 Chrome 打开这个地址，然后
**Chrome 菜单 `⋮` →「添加到主屏幕」**——桌面就会出现蓝色日历图标，
点开是全屏、无地址栏，**断网也能用**（Service Worker 已预缓存全部资源）。

打不开的话，多半是 Windows 防火墙拦了 Node.js，允许它通过「专用网络」即可。

### v1.11.0：打包成安卓 APK · 备份覆盖全部 7 张表

这一版做的是**「要一个数据独立存储的安卓应用」**这个诉求。

#### 一、修了一个会丢数据的原有 bug（最重要）

「导出 JSON 备份」再「从 JSON 导入」，**活动会全部消失，而且不报任何错**。

根因在字段命名不一致：

| 环节 | 用的字段名 |
|---|---|
| `Event` 构造函数 | `startTime`（camelCase） |
| `Event.toJSON()` 输出 | `start_time`（snake_case，与 SQLite 列名一致） |
| `bulkAdd()` 导入 | `new Event(item)` ← 直接吃 snake_case 对象 |

于是 `startTime` 变成空串 → `validate()` 失败 → 记录被静默跳过。
表现就是 toast 显示「已导入 0 个活动」，用户以为备份是空的。

修法是让 `bulkAdd()` 走 `Event.fromRecord(item)` —— 它本来就同时兼容两种命名，
是唯一正确的入口。这个 bug 在 v1.10.0 及更早版本一直存在。

#### 二、备份从「只含活动」扩展到全部 7 张表

之前 `exportJSON()` 只导出 `events` 一个 store，打卡 / 记账 / 待办 / 账户 / 预算
**都不在备份里**。而设置页文案写的是「把全部活动导出」—— 严格说没错，
但极易被读成「导出我的全部数据」，靠它换机就会丢一大半。

现在导出格式升到 `version: 2`，覆盖全部 7 个 store：

| store | 中文名 | 导出方式 |
|---|---|---|
| `events` | 活动 | `toJSON()`，**不含 id**（保持 v1 格式兼容） |
| `checkins` | 打卡项 | 原始记录，**保留 id** |
| `checkin_logs` | 打卡记录 | 原始记录，**保留 id** |
| `ledger` | 记账流水 | 原始记录，**保留 id** |
| `todos` | 待办 | 原始记录，**保留 id** |
| `accounts` | 账户 | 原始记录，**保留 id** |
| `kv` | 预算 / 设置 | 原始记录 |

> 为什么其余 6 个不能也用 `toJSON()`：`ledger.accountId` 指向 `accounts.id`、
> `checkin_logs.checkin_id` 指向 `checkins.id`，都是**真外键**。
> 而 `Account.toJSON()` 是**故意不含 id** 的（那是给「导入单个账户」用的），
> 拿它做备份会让还原后的关联全部断裂。

导入时可选**合并**或**替换**，并**重新分配整数 id + 同步重映射外键**，
所以合并两份来自不同设备的备份也不会 id 撞车。
`accounts.entries[].id` 是字符串（`e<时间戳><序号>`），全局唯一，原样保留。

向后兼容：`纯数组`（最早期）、`{events:[...]}`（v1）、多表对象（v2）三种形态都能导入。

#### 三、Capacitor 安卓壳（打包 APK）

用 **Capacitor 套壳**，现有网页代码**零重写** —— 所有功能、所有测试原样复用，
只是运行环境从 Chrome 换成应用自带的 WebView。

| | PWA | APK |
|---|---|---|
| 数据存在哪 | 浏览器 IndexedDB，**按网址隔离** | **应用私有目录** |
| 依赖电脑开着 | 要 | **不要** |
| 换 Wi-Fi / IP 变了 | 打不开 | 不受影响 |
| 手机与电脑数据 | 两套互不相通 | 不涉及 |
| 自动备份 | 无 | ✅ 自动写手机文件 |

**关键技术点**：项目零构建、零依赖，`web/` 直接当静态目录伺服，
浏览器解析不了 `@capacitor/filesystem` 这类裸模块名。所以没有用插件的 npm JS，
而是走 Capacitor 注入 WebView 的低层通道：

```js
window.Capacitor.nativePromise('Filesystem', 'writeFile', { ... })
```

这样**不需要打包器、不需要 import map、不需要把插件 JS 塞进 `web/`**，
与项目原则一致。详见 `web/js/services/native_bridge.js` 顶部注释。

在普通浏览器里 `window.Capacitor` 不存在，桥接层全部安全降级为 no-op，
**网页版行为完全不受影响**（`verify_backup.mjs` 第 7 组专门守这条）。

#### 四、自动备份（仅 APK 内生效）

- **落点**：`Documents/周周记备份/`，逐级回退 Documents → ExternalStorage → 应用私有目录
- **时机**：数据改动后防抖 5 秒；应用切到后台时立刻再写一次
- **文件**：`周周记-最新备份.json` + `YYYY-MM-DD.json`（按天留档，保留 7 份）
- **手动**：设置 → 自动备份到手机 → 立即备份 / 分享备份文件
- 同时**跳过 Service Worker 注册** —— 资源已打进 APK，再套一层 SW 缓存
  只会让应用升级后继续喂旧文件

#### 五、依赖仓库改过（构建相关）

Capacitor 默认模板用 `google()`，它解析到 **maven.google.com**，
该域名在部分网络下不可达。已把 4 处改成 `dl.google.com/dl/android/maven2` 直连
（实测是其同一份内容）+ 阿里云镜像兜底。

⚠️ **`npx cap sync android` 会重新生成

所以 `npm run android:sync` 后面自动挂了 `tools/patch_gradle_mirrors.mjs` 重打一遍

1. **项目路径含中文**（`D:\desktop\周历记`）→ AGP 直接拒绝构建。
   已在 `android/gradle.properties` 加 `android.overridePathCheck=true`。
2. **Adoptium 官方 API 只有 23 KB/s** → 换清华镜像，13 秒下完。
3. **`sdkmanager` 解压 `platforms;android-36` 会失败**（内置解压器在 Windows 上的

6. **`signingConfigs` 必须写在 `buildTypes` 前面** → Groovy DSL 顺序求值，

具体做法是每个导航项渲染**两个字形**，叠在同一位置做交叉淡入淡出：

| 状态 | 字形 | 表现 |
| --- | --- | --- |
| 未选中 | `calendar` / `record`（描边版） | 细线轮廓，灰蓝色 |
| **选中** | `calendarSolid` / `recordSolid`（**实心版**） | **整块填充品牌蓝** |

- 实心字形用 `fill-rule="evenodd"` 在内部挖出镂空（日历的两个日期点、
  记录的白色对勾、顶部活页环），所以白色缝隙是**真实镂空**而不是描边叠加，
  缩到 21px 也不会糊。
- 填充色写的是 `currentColor` 而不是硬编码蓝色 —— 这样父级的 `color` 过渡
  能**同时驱动图标填充和文字变色**，两者颜色永远一致，改主题色只需改一处。
- 实测墨迹覆盖率：描边版约 32–35% → **实心版约 62–67%**，接近翻倍。
- 小圆点指示器（`::after`）已彻底移除。

> 未选中的描边版仍然照常用于其他位置（分段控件、设置页等），
> 实心版 `calendarSolid` / `recordSolid` **只服务底部导航的激活态**。
> 新增图标时若要做激活态，记得一并加实心版 —— 少了它激活时会变成空白。

回归脚本：`node tools/verify_nav_icon.mjs`（25 项，含双字形交叉淡入淡出、
颜色一致性、墨迹覆盖率、切换 tab 后激活态转移、小圆点已移除）。

### v1.9.0：月扣款只在约定那天执行 · 账户消费不再进总账

两个改动都是**修正语义**，不是加功能。

#### 一、每月扣款不再「设置完就立刻扣」

之前的实现有个容易踩坑的地方：给账户设好月扣款后，如果**当天已经过了**
你填的扣款日，系统会立刻扣掉一笔（因为「这个月的扣款日已经到了」）。
用户要的是相反的：

> 「月扣款的时候不是设置了立即扣除，而是在固定的设置的那一天扣款。
>  要是设置日期在扣款之前，到扣款日期就扣；
>  要是设置日期在扣款之后，那么就不管他，下个月扣款日再扣。」

现在的规则：

| 你设置的那天 | 这个月扣不扣 | 什么时候扣 |
| --- | --- | --- |
| **早于**扣款日（如 15 号设、25 号扣） | 扣 | 本月 25 号 |
| **等于**扣款日 | 扣 | 当天 |
| **晚于**扣款日（如 15 号设、10 号扣） | **不扣** | 下个月 10 号 |

配套的三条：

- **设置当时永远不扣款** —— 设置完只落一个「已设置」的提示，余额不变。
  提示文案会直接告诉你下次什么时候扣（「已设置：下个月 10 号扣 ¥500.00」）。
- **`since` 一旦打上就不再改写**。只改金额 / 日期 / 备注时，
  不会把起点推到本月 —— 否则「本来就该这个月扣的那期」会被悄悄跳过。
- 只有**改金额**才会让「期数」重新从第 1 期算起。

**好几个月没打开 App 怎么办？** 会**逐月补齐**，不设上限 ——
房租本来就是要交的。例如 10 月的扣款日过了，你 12 月才打开，
10 / 11 / 12 三期会一起补上。

自动扣款落下的流水备注会带上期数，一眼能分清是不是月扣款：

```
房租（第 3 期 / 共 12 期）
```

> 内部实现：`recurring.sinceSkip` 记住「启用月那一期是不是已经放弃」，
> `recurring.lastRun` 是「已执行到哪个月」的唯一权威。
> `dueRecurring(today)` 仍是**纯函数**（可单测），`runDueRecurring()` 才落库，
> 在进入账户页时调用。

#### 二、账户「消费」不再镜像进记账总账

v1.7.0 曾让账户的**充值和消费**都镜像到记账页，口号是「记账页是全部资金流动的总账」。
实际用起来问题很明显：**同一笔钱会被算两遍**，月度支出凭空翻倍。

现在收窄为：

| 账户动作 | 记账总账 | 分类 |
| --- | --- | --- |
| **充值** | ✅ 记一笔收入 | `acct_in` |
| **消费** | ❌ **不进总账** | —— |
| 每月扣款（充值方向） | ✅ 记一笔收入 | `acct_in` |

一句话：**账户只管余额，记账只管花费。** 日常消费在记账页自己记一份就够了，
账户侧再镜像一次就是重复计算。

- 记账页里对应的角标也从「· 来自账户」细化为「**· 来自账户 · 充值**」。
- **旧数据会自动清理**：v1.7–v1.8 期间已经镜像过去的 `acct_out` 支出记录，
  在进入记账页或账户页时清一次（只跑一次，用 `kv` 标记去重）。
  充值镜像（`acct_in`）保留 —— 那是你想要的。


一个小但影响对账体验的改动：**给账户充值时的备注从「可跳过」改为必填**，
标题也从「备注（可跳过）」改成「这笔钱的来源」。

理由：充值来源是这笔钱的凭证。跳过后记账页只剩一个孤零零的金额，
日后对账时分不清是工资、奖学金、报销还是退款 —— 而这恰恰是本功能存在的意义。
示例文案也一并换掉了（原来是「爸妈转账」，现在引导写「工资」「奖学金」「报销」「退款」）。

**只有充值是必填，消费的备注仍然可以跳过** —— 刷一次卡记一次的场景太多，
每笔都强制写用途反而添麻烦。

实现上给 `promptDialog` 加了 `required` 选项：
空内容点保存时**弹窗不关闭**，就地显示红色提示「请填写这笔钱的来源」，一输入即消失。
之所以做进弹窗内部而不是让调用处判断 `if (!note) return`，是因为
`promptDialog` 对「空提交」和「点取消」返回的都是 `null`，
调用处分不清两者，会造成「点了保存却什么都没发生」的静默失败。

### v1.7.0：记账成为总账 · 账户可滚动 · 每月定时扣款

四个改动，前两个直接来自用户反馈的 bug。

#### ① 待办与记账调换位置

分段控件顺序由「打卡 / 记账 / 待办 / 账户」改为 **「打卡 / 待办 / 记账 / 账户」**，
高频的待办紧挨着打卡，记账往后排。

#### ② 账户金额变动同步到记账（记账页 = 全部资金流动的总账）

用户原话：

> 「我往卡里冲了多少钱，那么账单显示我这一笔钱花了多少钱往哪里冲
> （意思是记账的账单是所有的消费金额）」

以前在账户页充值 / 消费只落在账户内部，记账页看不到，用户会以为「钱凭空少了」。
现在账户侧的**每一笔流水都会镜像一条记账流水**：

| 账户动作 | 记账页生成 | 分类 | 备注 |
| --- | --- | --- | --- |
| 充值 | 收入 | 账户充值 | `账户名 · 你填的备注` |
| 消费 | 支出 | 账户消费 | `账户名 · 你填的备注` |
| 对账差额补记 | 收 / 支 | 对应类目 | 同上传入的备注 |
| 每月扣款 | 支出 | 账户消费 | `账户名 · 每月扣款` |

实现要点（都在 `account_service.js`）：

- 新增两个**系统分类** `acct_out` / `acct_in`，带 `system: true` 标记。
  `ledgerCategoriesOf()` 会把它们过滤掉 ——
  否则用户在「记一笔」里也能选「账户充值」，账就串了。
- 记账条目新增 `account_id` + `account_entry_id` 两个字段，
  用 `(accountId, accountEntryId)` 做**去重键**，重复调用不会产生多条。
- **三处级联**：删账户流水 → 删对应记账流水；删账户 → 清掉它全部镜像；
  账户镜像的流水在记账页**只读**（点开是说明抽屉，引导回账户页操作），
  这样两边永远对得上。
- 镜像失败**不回滚**账户流水：账户余额是用户的核心数据，
  不能因为附加的记账写入失败就把用户的输入丢掉。

#### ③ 修复：账户界面无法上下滑动

用户原话：「多个账户的同时，会导致只能看见第一个账户不能看到其他的账户」。

**根因**：账户视图是四个子视图里唯一没有沿用 `.app-body` 的
（根节点是 `.acct-view`，见 `account_view.js:45`），
于是它既拿不到 `flex: 1` 也没有 `overflow-y: auto` ——
内容溢出后被 `.record-body-host` 的 `overflow: hidden` 直接裁掉。

**修复**：在 CSS 里补上滚动能力，而不是把类名改成 `.app-body`
（那样会连带套上 `.app-body` 的其它规则，风险更大）：

```css
.record-body-host > .acct-view {
  flex: 1;
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;
  -webkit-overflow-scrolling: touch;
  scroll-behavior: smooth;
  padding: 10px 14px calc(var(--nav-h) + 22px);  /* 与 .app-body 留白一致 */
}
```

> ⚠️ 记录一个测试坑：`.acct-view` 与 `.app-body` 一样带 `scroll-behavior: smooth`，
> 所以 E2E 里 `el.scrollTop = el.scrollHeight` 之后**立刻读 `scrollTop` 是 0**
> （平滑滚动是异步动画）。必须等动画跑完再读。

#### ④ 每月定时扣款（可选择性地给每个账户开关）

用户原话：「账户里面每一个账户的多一个功能就是可以每个月按时扣款（这个选择性设置）」。

适合房租 / 话费 / 会员费这类固定支出，不用每月手动记一次。

| 项目 | 说明 |
| --- | --- |
| 入口 | 账户卡片上的「定时」按钮，或右上角「⋮」菜单里的「设置每月扣款」 |
| 可配项 | 金额、每月几号（**1–28**）、备注、方向（扣款 / 充值） |
| 生效时机 | 每次进入「账户」页时自动补齐所有已到期月份（幂等） |
| 防重复 | `recurring.lastRun` 记月份，同一个月只扣一次 |
| 防倒扣 | `recurring.since` 记启用月份，**不会倒扣启用之前的月份** |
| 可视化 | 账户名旁的「每月扣款」徽标 + 卡片内的紫色说明条 + 本次补扣的汇总提示条 |

`recurring` 是账户上新增的持久化字段：

```js
{ enabled, day, amount, note, kind, since, lastRun }
```

> **旧数据兼容**：v1.6 及以前保存的账户没有 `recurring` 字段，
> `normalizeRecurring()` 会兜底成「未启用」，
> 不会崩、也不会显示一个凭空的扣款承诺。

日期上限取 28 是刻意的：29–31 号在有的月份不存在，
与其每月做「月末兜底」的隐式跳跃，不如直接限制范围、让用户填一个每月都存在的日子。

### v1.6.0 视觉改版：液态玻璃

参考「生活流」的视觉语言，做了三件事。**没有引入任何依赖、没有任何构建步骤**，
全部是 CSS 与少量 DOM 结构 —— 玻璃质感靠 `backdrop-filter`，不需要图片资源。

#### ① 景深：卡片下面露出「还有更多」的边缘

`--depth-1-y` / `--depth-2-y` 两个令牌控制两层伪元素（`::before` / `::after`）
在主卡下方露出的高度（7px / 14px）。
主卡（账户卡、记账汇总卡、总余额卡）带这层景深，信息层级一眼就分得清。

#### ② 玻璃：半透明 + 背景模糊 + 内高光

三个令牌分工明确：

| 令牌 | 作用 | 关键点 |
| --- | --- | --- |
| `--glass-1/2/3` | 表面白度（0.72 / 0.58 / 0.44） | 用 0.72 而非纯白，因为 `backdrop-filter` 会再提亮 |
| `--glass-hi` | 顶部一道内高光 | **玻璃"有厚度"的关键**，缺了就只是半透明色块 |
| `--blur-card/dock/sheet` | 模糊强度 14 / 22 / 30px | 越靠前的层越模糊，符合物理直觉 |

页背景也加了三处径向光晕（`--bg-glow-a/b/c`）——
**玻璃必须有东西可模糊**，叠在纯色上会看起来像没生效。

#### ③ 悬浮：玻璃 Dock + 中央圆形按钮

底部导航从「贴底白横条」改成**上浮的毛玻璃浮岛**（左右各留 10px 透气、22px 圆角），
中央加号变成**直径 58px 的圆形渐变大按钮，跨出 dock 上沿 19px**，
外加一圈白色描边把它从 dock 上「切」开。

> ⚠️ 这里踩过一个坑：用 `align-self: center` 配负 `margin-top` 时，
> flex 分配剩余空间会**把 margin 一起算进去**，写 `-24px` 实测只上浮 9px。
> 改成 `align-self: flex-start` + 负 margin 后位移量才等于 margin 本身。

#### ④ 快速记录抽屉（QuickSheet）

点底部「＋」不再直达添加页，而是弹出一个毛玻璃抽屉：

- **上半区** 2×2 彩色玻璃卡（有渐变图标底座）：识图记账 / 记一笔 / 新增账户 / 新建待办
- **分割线**
- **下半区** 2×4 轻量功能行（只有彩色线性图标）：去打卡 / 看周历 / 待办清单 / 粘贴通知
- 底部居中「取消」，整块可下拉（顶部有 `grabber` 把手）

抽屉不只是「导航菜单」——点「记一笔」会**直接落到记账页并把表单摊开**
（`ctx.go('record', {tab:'ledger', action:'entry'})`），少一次页面往返。

#### ⑤ 其他玻璃化

分段控件改为胶囊（激活项是凸起的白色胶囊）、
事件卡 / 列表卡 / 提示条 / 模态 / 底部面板 / Toast 全部改为玻璃质感，
遮罩从纯压暗改为「压暗 + 模糊」，让底层内容失焦。

### v1.5.0 新功能：账户余额对账 · 使用说明 · 安卓安装

四个改动，围绕「把账握在自己手里」和「真正装到手机上用」。

#### ① 待办空态：直接进管理界面

以前一条待办都没有时，整屏只显示一个空状态页，想新建还得先点一下。
现在**空态也照常渲染汇总卡和三个分区**（任务 / 想要 / 已完成），
并在分区下方内联两个按钮（新建任务 / 新建想要）——**一眼就知道这页是干什么的**。

#### ② 账户余额对账（核心）

用户原话：

> 「我充饭卡，我饭卡有多少金额，我消耗了多少金额，还剩下多少金额……
> 目的在于不把『我还剩多少钱』全依靠给第三方平台，
> 好明确知道自己的钱有没有被误吞或者误扣而导致减少而没记录。」

记账页新增第四个分段 **账户**。它不只是「显示余额」，核心是**对账**：

| 口径 | 含义 |
| --- | --- |
| **推导值** | 期初余额 + 你记的充值 − 你记的消费 |
| **快照值** | 你去平台 / 卡机上抄下来的实际余额 |
| **差额** | 两者之差 —— **这就是「钱有没有被误扣」的答案** |

差额方向的解释是明确写出来的：

- 差额为正 → **平台扣得比你记的多** → 可能有没记的消费，或者被误扣了
- 差额为负 → **你记的比平台扣的多** → 可能有重复记录，或者有笔充值没记
- 差额 ≈ 0 → 对得上，这本账是准的

对账时可以选择**补记差额**（自动补一笔流水把账面调平），或**只留对账记录**
（先弄清来源再说）。补记后提示条从橙色警告转为绿色「对得上」。

其他能力：

- 五种账户类型：🍚 饭卡/校园卡 · 🏦 银行卡 · 💵 现金 · 📱 零钱 · 📦 自定义
- 卡片显示：当前余额 / 累计充值 / 累计消耗三项，外加期初余额与日均消耗预估
- **日均消耗 + 还能用多久** —— 按「有消费记录的天数区间」估算（最多看最近 90 天），
  `还能用 X 天`；剩不到 7 天转为橙色提醒
- 账户流水单独记（最多显示最近 8 条，可看全部），与记账页的收支流水互不干扰
- 账户可归档（暂不显示但数据保留）
- **没设过期初余额的账户不显示推导数字** —— 否则会拿 0 当基准算出
  「已花 ¥0」这种假数据，转而提示「先填一下当前余额」

#### ③ 设置 → 使用说明（只讲输入格式与陷阱）

用户要求：**「主要就是本软件的一些输入格式等问题，而不是教别人一眼就知道该怎么使用的那些功能」**。

所以这份说明**不写操作步骤教学**，只讲三件事，全部用 ✅ / ❌ 对照：

1. **输入格式** —— 什么写法能被识别，什么写法会踩坑（时间、地点、学术活动、就业类）
2. **已知陷阱** —— 型号当价格（`g27`）、四位数当年份、OCR 行序、多行粘贴
3. **数据安全警告** —— 清缓存 / 卸载会永久删数据，必须先导出备份

共 6 个主题：活动通知 · 记账金额 · 账户对账 · 待办与打卡 · 图片识别 · 数据安全，
顶部有可横向滑动的目录，点一下滚到对应小节。

#### ④ 可安装到安卓手机（PWA）

现在符合 PWA 标准，**可以直接装到安卓主屏幕，全屏运行、离线可用**：

- `manifest.webmanifest` —— standalone 显示模式、四张图标（含 maskable）
- `sw.js` —— Service Worker，**预缓存 53 项资源**，静态资源走「缓存优先 + 后台更新」，
  导航请求走「网络优先 + 失败回落」
- 图标是**手写 PNG 编码器**生成的（`tools/make_icons.mjs`），
  不为了两张图引入 sharp / canvas —— 应用本体的零依赖原则不破
- 本地服务器默认绑 `0.0.0.0` 并**打印局域网地址**，手机连同一 Wi-Fi 直接访问

`npm run pwa` 一键同步 Service Worker 版本号与预缓存清单，
`npm run pwa:check` 校验 PWA 完整性（CI 可用）。
完整安装步骤、APK 打包路径与排错清单见 **`06_安卓安装与部署.md`**。

#### 版本号只有一个真源：`package.json`

`npm run pwa` 会把版本号**分发**到下面三处，任何一处都不许手写：

| 位置 | 用途 | 怎么来的 |
|---|---|---|
| `package.json` | **唯一真源** | 手动改这一处 |
| `web/js/version.js` | 设置 →「关于」里显示 | 由 `build_pwa.mjs` 生成 |
| `web/sw.js` 的 `VERSION` | 缓存键（不改就吃旧缓存） | 由 `build_pwa.mjs` 生成 |
| 安卓 `versionName` / `versionCode` | 决定能否**覆盖安装** | gradle 直接读 `package.json` |

> 🔴 **为什么较这个真**：设置页原来把版本号硬编码成 `v1.12.0`，
> 而 `package.json` 已经到 1.13.1 —— 用户判断「这次更新装上了没有」看的正是这一行，
> 它在撒谎。现在 `tools/verify_pwa.mjs` 有一条断言钉住「页面显示的版本 == package.json」，
> 并已用负向测试确认它会红。

### v1.4.1 修复：记账金额识别（型号混入 / OCR 行序）

两个用户实际踩到的问题，一起修掉：

| 问题 | 之前 | 现在 |
| --- | --- | --- |
| 第一个数字是**型号** | 「买显示器 **g27**」→ 金额被填成 **27** | 金额留空并提示「没能识别出金额，请手动填写」，**绝不把型号当价格** |
| 截图 OCR 时**小额串到前面** | 「付款成功 / 吃早饭0.65 / 15.80」→ 金额变成 **0.65**（行序一换结果就变） | 结果与行序**完全无关**，稳定取到 **15.8** |

具体做法：

- **型号守卫** —— 数字左边紧贴拉丁字母（`g27` / `iPhone15` / `A4`）不作金额；
  卡号（`6222 0212 3456 7890`）、订单号（7 位以上 / 含千分位）不作金额；
  年份（`2026年`）、中文量词（`3杯` / `2份`）不作金额
- **行序无关** —— 带货币记号（`¥` / `元` / `块钱`）的候选统一收集后比较，
  不再「谁先出现就用谁」；「实付 / 金额 / 合计」同行仍然最优先
- **一句话兜底** —— 没有货币记号时，只认**行尾那个唯一的数字**（`午饭100` → 100）；
  一行里有两个数字（`买显示器 g27`）时**宁可留空也不猜**
- **顺手修了一个隐藏硬伤** —— 粘贴窗原本是单行输入框，而支付截图的 OCR 文本
  **天然是多行**，用户根本粘不进去。现在改成多行文本框（Enter 换行，Ctrl+Enter 解析）

> 设计原则：**金额错了比金额空着代价大得多**（用户会照错数记账），
> 所以模型宁可「认不出就留空 + 明确提示」，也不猜一个填进去。

### v1.4 新功能：待办（任务 / 想要）

「记录」页新增第三个分段：**待办**。一个模型装两种形态：

| 类型 | 颜色 | 用来记什么 | 例子 |
| --- | --- | --- | --- |
| **任务** | 🔵 蓝 | 有明确要做 / 要交的事 | 交实验报告、开组会、还书 |
| **想要** | 🟠 橙 | 想做的事、想买的东西 | 看那部新电影、买双跑鞋 |

**区分靠「颜色 + 折叠」双管齐下**，两者叠加才既快又清：

- **颜色**：分区左侧色条、条目左侧色条、类型徽标，三处都按类型上色，
  折叠状态下也能一眼认出这是哪一类
- **折叠**：未完成按「任务 / 想要」分成两个**可折叠分区**，点标题栏展开收起；
  **已完成整体沉到最下面并默认收起**（`已完成 [3] ›`），不干扰未完成的主线

其他能力：

- 点左侧圆圈**勾选完成**，条目立刻沉进「已完成」；再点一次可恢复
- 顶部汇总：待完成 / 已完成 / 已逾期，逾期条目自动标红
- 可选**截止日期**，显示为「今天 / 明天 / 3 天后 / 已逾期 2 天」这种人话
- 长按条目（点标题）打开菜单：改类型、设截止日、编辑标题、删除
- 「已完成」分区带**清空**按钮，一键清掉所有已完成项

### v1.3 新功能：记录页（打卡 + 记账）

底部导航原来的「历史」替换为「**记录**」，一个页面装三个功能，顶部切换。

**打卡** —— 自己设置打卡项标题（背单词 / 跑步 / 早睡…），点进去就是当月月历：

- 月历上**已打卡**（蓝色打勾）、**未打卡**（浅灰）、**还没到的日期**（更浅、不可点）三种状态一眼分清
- 点任意已过去的日期可以**补打卡**或**取消打卡**
- 自动统计：**连续天数**、本月打卡天数、本月完成率、历史最长连续
- 列表页支持「今日打卡」一键开关，顶部圆环显示今日完成进度

连续天数的口径：今天没打卡**不算断卡**（当天还没结束），从今天或昨天起算连上的一段。

**记账** —— 金额 + 收 / 支 + 分类 + 备注 + 日期：

- 月度汇总卡：支出 / 收入 / 结余，支出红、收入绿
- **全局月度预算**：进度条 + 按已过天数的参考线；超支标红，进度偏快标黄
- 支出构成（分类占比）+ 近 6 个月支出柱状图
- 流水按日分组，组头显示当日合计
- **一键导入**：截图走本机离线 OCR、或直接粘贴文字，自动填金额 / 收付 / **备注（这笔钱干什么用了）** / 分类 / 日期，**核对后**再保存（识别结果永远不当事实直接入库）
- **备注识别**（v1.3.2）：不只会给一个分类，还会抓出具体用途

```
收款方 瑞幸咖啡        → 备注：瑞幸咖啡
实付 ¥32.80 商家 麦当劳 → 备注：麦当劳
午饭 12.5 元           → 备注：午饭
星际烤肉店 28 元        → 备注：星际烤肉店
9月15日 食堂午饭 15元   → 备注：食堂午饭
```

「微信支付」「支付成功」这类 App 名与交易状态词**不会**被当成备注 ——
它们只说明「用哪个 App 付的、成没成」，不说明「买了什么」。
若整段文字确实读不出用途，表单会明确提示你去补备注，而不是默默留空。

内置 12 个记账分类（餐饮 / 交通 / 学习 / 日用 / 娱乐 / 医疗 / 居住 / 其他支出 + 生活费 / 兼职 / 奖助学金 / 其他收入）。

### v1.3 周视图改动：不再显示「第几周」

顶部只显示 **本周 / 上周 / 下周** 与 **日期区间**（如 `9月14日 - 9月20日`），


### 地点

```
地点：数学学院201报告厅         报告地点：信息楼A201
本次会议在社科楼A101举行        于图书馆学术厅举办
独立成行的「外语楼B301」        9.18 14:30 说明会 外语楼B301
```

### 名称

```
报告题目：图论中的均衡染色问题   讲座题目：人工智能前沿进展
活动名称：2026级新生开学典礼     主题：新能源材料发展
宣讲单位：华为技术有限公司       内容：食堂满意度座谈会

```

**叙述式通知**（没有「题目：」字段，题目藏在句子里）也支持：

```
…在博学楼B412会议室举行讲座，主题为：考虑交易成本的最优均值回归trading策略，欢迎大家参加！
                ↓
标题：考虑交易成本的最优均值回归trading策略
```

> 名称解析会保留企业名、届次、引号修饰与破折号后缀，**不会**只截取引号内的几个字。
> 微信/公众号常见的 `~~波浪线~~`、`**加粗**` 标记会自动去除。
> 「主题为：」之后的内容会被优先当作题目，因此句尾的「在群内进行活动签到」这类干扰句不会污染标题。

```

报告人：张三、李四（取首位） 报告人：张伟（清华大学）
报告人：                  本次讲座由孙七教授主讲
赵六                     特邀周八博士作报告
```

**英文姓名**同样支持（外籍 / 海归学者）：

```

邀请到香港理工大学商学院 Harry Zhang 教授于9月28日举行讲座

                ↓
```

> 职称、学位后缀（教授 / 副教授 / 副研究员 / 博士生导师 / 院士…）会被自动剥离，并按**长后缀优先**匹配 ——
> 保证「李敏副教授」得到「李敏」而不是「李敏副」。
> 「各位同学」「时间」「地点」这类明显不是姓名的内容会被拒绝，「Professor Smith」中的职称前缀也不会被当作姓名。

### 分类判定的边界规则

三分类不是简单的关键词命中，几条容易踩坑的边界都已处理并有测试覆盖：

| 输入 | 判定 | 原因 |
| --- | --- | --- |
| 学术研讨会 / 学术论坛 / 学术沙龙 / 新能源材料发展论坛 | 学术 | 会议、报告、讲座、论坛统一归学术 |
| 「数字经济与就业」专题讲座 | 学术 | 明确强词「专题讲座」不被伴随词「就业」抢成就业 |
| 学院教学工作研讨会 | 其他 | 「教学工作」是内部事务词，命中即否决（否则会被「研讨会」带进学术） |
| 年度科研工作总结 / 党委会 / 论文答辩 | 其他 | 内部事务词否决 |
| 就业宣讲会暨产学研论坛 | 就业 | 宣讲会形态明确，优先于论坛 |
| 活动地点：材料学院学术报告厅 | 按正文判 | 地点字段不参与分类（否则「报告厅」会污染判断） |

## 五、OCR 图片识别（可选）

使用的是 **Windows 系统自带的离线 OCR 引擎**，图片不会离开你的电脑。

1. 双击 **`tools/启动OCR服务.bat`**（首次运行会自动安装约 15MB 的 winrt 运行库）
2. 看到 `[OK] OCR 引擎已就绪` 后保持窗口开着
3. 在应用里点「添加」→「截图识别」→ 选择截图（或直接 `Ctrl+V` 粘贴、拖拽图片进去）
4. 识别出的文字可以编辑，确认后点「提取字段」

**没有启动 OCR 服务也能正常用整个应用** —— 只是「截图识别」会提示你先启动服务，改用「粘贴文字」即可，不会崩溃。

> 更省事的替代方案：用微信或系统相册自带的「提取文字」，把文字复制出来粘贴到「粘贴文字」页。

## 九、数据存储与备份

- 数据保存在**本机浏览器**的 IndexedDB，数据库名 `campus_week_calendar`
- v1.5.0 起共 **7 个存储**（DB_VERSION = **4**，从旧版升级会自动建表，原数据不动）：
  `events`（活动）、`checkins`（打卡项）、`checkin_logs`（打卡记录）、
  `ledger`（记账流水）、`kv`（月度预算等设置）、`todos`（待办：任务 / 想要）、
  `accounts`（账户：饭卡 / 银行卡等，含流水与对账快照）
- 活动表结构与 `03_技术架构与开发指南.md` 的 SQLite 设计完全一致：

  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | `id` | INTEGER PRIMARY KEY AUTOINCREMENT | 自增主键 |
  | `title` | TEXT NOT NULL | 活动名称 |
  | `location` | TEXT NOT NULL | 活动地点 |
  | `start_time` | TEXT NOT NULL | 活动时间 `YYYY-MM-DD HH:mm` |
  | `raw_text` | TEXT | 通知原文 |
  | `created_at` | TEXT NOT NULL | 创建时间 |
  | `category` | TEXT | 分类（academic / job / other） |
  | `speaker` | TEXT | 报告人（仅学术类） |

- **清理浏览器数据 / 卸载浏览器会导致数据丢失。** 建议定期在「设置 → 导出 JSON 备份」保存一份。
- **v1.11.0 起导出的是全部 7 张表**（活动 / 打卡 / 打卡日志 / 账户 / 记账 / 待办 / 设置），
  不再是「只有活动」；导入时可选**合并**（追加，id 自动重分配）或**替换**（先清库），
  并兼容 v1.11.0 之前只含活动的旧备份。
- 装成 **APK** 后（见 `06_安卓安装与部署.md`），应用还会**自动把备份写到手机文件**
  （`Documents/周周记备份/`），换机或误删时可从这里恢复。

### 记账流水与账户的关联（v1.7.0 / v1.9.0）

`ledger` 表新增两个可选字段，用于标记「这条流水是从哪个账户镜像过来的」：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `account_id` | INTEGER | 来源账户 id；为空表示是手动记的流水 |
| `account_entry_id` | TEXT | 来源账户内部流水 id，与 `account_id` 组成去重键 |

> **v1.9.0 起只有「充值」会产生镜像**（分类 `acct_in`），
> 账户消费不再进记账总账，避免同一笔钱被算两遍。

`accounts` 表的 `recurring` 字段（每月扣款配置）：

| 子字段 | 类型 | 说明 |
| --- | --- | --- |
| `enabled` | BOOLEAN | 是否启用（还需 `amount > 0` 才算真正生效） |
| `day` | INTEGER | 每月几号，**1–28**（避开不存在的月末日期） |
| `amount` | REAL | 金额，正数 |
| `note` | TEXT | 备注，如「房租」 |
| `kind` | TEXT | `out` 扣款（默认）/ `in` 充值 |
| `since` | TEXT | 生效起始月份 `YYYY-MM`，防止倒扣启用前的月份；**重设时不刷新** |
| `lastRun` | TEXT | 上次执行的月份 `YYYY-MM`，防止同月重复扣；**判定是否该扣的唯一权威** |
| `runCount` | INTEGER | 已自动执行的期数（v1.9.0），仅用于「第 N 期 / 共 M 期」展示 |
| `sinceSkip` | BOOLEAN | 启用月那一期是否已放弃（v1.9.0）；设置日已过扣款日时为 `true` |

## 十二、设计原则

1. 简单
2. 手机端优先
3. 离线优先
4. 不调用收费 API、不消耗 Token
5. 数据本地存储
6. **自动识别后必须人工确认**
7. 不擅自增加复杂功能

开发原则（来自 03 文档）：UI 与数据库逻辑分离、OCR 与解析逻辑分离、正则不写死在页面中、每个 Parser 独立可测、不过度设计、不提前引入服务器、保证每个阶段都可运行。
