# 数据存储 · 命名与版本

## 一、技术栈与存储

- **原生 HTML/CSS/JS + ES Module，零依赖、零构建**；目录 `web/js/{models,services,screens,widgets,utils}/`。
  **所有正则集中在 `web/js/utils/regex_patterns.js`**，禁止写死在页面里（硬性要求）。
- **IndexedDB**：库名 `campus_week_calendar`，**DB_VERSION = 4**，**7 个 store**：
  `events` / `checkins` / `checkin_logs` / `ledger` / `todos` / `accounts` / `kv`。
  升级走 `onupgradeneeded` 且**只新增缺失的 store**，不能重建。
  新增字段必须保证旧记录可读（`fromRecord` 给默认值）；分类 id 变更必须走 `normalizeCategory()`。
- **OCR 有两条路径，按环境自动选**（v1.12.0 起）：
  - **手机（原生）** → 设备端 **ML Kit 中文离线识别**（`@capacitor-mlkit/text-recognition`）。
    图片写进 `CACHE` 目录 → 识别 → `finally` 里删掉，**图片不出手机**。
    模型打进 APK，不依赖 Google 服务。
  - **电脑浏览器** → 本机 Windows.Media.Ocr（`tools/ocr_server.py`），离线零费用；
    未启动时降级提示改粘贴文字，**不能崩**。
  - 两条都不可用时，降级文案由 `ocrService.failureHint` 给，**不许抛到界面上**。
- 🔴 **数据全在本地，零上传**。两处别混：**IndexedDB 存数据**、**Cache Storage 存代码**（sw 预缓存）。
- 🔴 **IndexedDB 按 origin 隔离** —— 电脑 `localhost:8080` 与手机 `10.x.x.x:8080` 是**两套数据**；
  局域网 IP 一变，已装的 PWA 就打不开（数据还在旧 origin 下）。
- 顶部栏 logo 用 `icons/icon-192.png` 图片（不是内联 SVG）；品牌源图 `assets/logo-3d.jpg`；
  资产预览页 `web/logo-preview.html`。

## 二、命名与版本

- 🔴 **正式名称「周周记」**（v1.8.0 起）；旧名「校园活动周历」**仅作副标题**保留在
  `description` / manifest description / 「关于」页标语行 / `logo-preview.html`。
  改名点：`index.html`（title / apple-mobile-web-app-title）、`manifest.webmanifest`（name / short_name）、
  `week_header.js` 的 `.app-header__title`、`settings_screen.js`；
  断言里一律用「周周记」（`e2e_test.mjs` 顶部标题、`verify_pwa.mjs` 的 `document.title`）。
  **旧名是「有意保留」，不是漏改，别顺手统一掉。**
- ⚠️ **`campus_week_calendar`（库名）与 `campus-week-`（sw 缓存 key）不跟着改名** —— 改名会丢数据。
- **版本号三处必须同步**：`package.json`（唯一真源）/ `web/sw.js` 的 `VERSION` /
  `settings_screen.js` 的 `VERSION`。**断言里不要写死版本号**，从 `package.json` 读。
- 安卓侧的 `versionCode` / `versionName` 由 `android/app/build.gradle` 用 `JsonSlurper`
  读 `package.json` 自动生成，不会与 Web 版脱节（见 `备份与安卓.md`）。
