22. **console 错误的来源看 `m.location().url`，不要只看 `m.text()`。**
    资源加载失败的消息文本永远是同一句 `Failed to load resource: net::ERR_XXX`，
    从文本里分不出是谁在报错。踩过：设置页探测 OCR 服务抛的连接被拒，
    `!/OCR/.test(m.text())` 挡不住，害得「无控制台错误」这条断言假红。
23. **算「元素在滚动容器里的位置」不能用 `offsetTop`。**
    `offsetTop` 是相对 **offsetParent** 的，而 `.app-body` / `.screen` 都没有
    `position`，它们的 offsetParent 一路找到 `#app` —— 量出来会比真实位置多出
    头部 + 筛选条 + 日期条那一整段（实测 205px）。
    正确写法：`sec.getBoundingClientRect().top - body.getBoundingClientRect().top + body.scrollTop`。
    踩过：周历页进入时自动滚到今天，多滚 205px，内容不够长时 scrollTop 被钳到最大值
    → **直接落到周日**（用户 2026-09-22 报的）。`npm run verify:week` 钉住。
24. **把元素从「默认可见」改成「默认隐藏」之前，先 `grep` 谁依赖它可见。**
    踩过：账户页「账户明细」改默认收起，一次波及 3 个脚本、5 个断言点。
    ⚠️ 还要区分两条路径：**走 UI 创建**（会拿到 `openCreate` 里的自动展开）
    和**直接调 API 播种**（拿不到）—— 别指望侧效应兜住，测试里显式点一次。
    ⚠️ 另外：**最后一个元素从「高卡片」变成「细开关」后，
    底部悬浮 dock 的遮挡风险突然变大**，要断言「滚到底后不被挡住」。
25. **`promptDialog` 的返回值是「三态」，不是布尔。**（用户 2026-09-22 报的
    「标注的可跳过的模块都不能跳过，一旦跳过就保存不了」的根因）
    - `null` = 取消（取消按钮 / Esc / 点遮罩 / 返回键）
    - `''`   = 用户**明确留空**（= 跳过这一项）
    - 其它   = 用户填的内容

    🔴 原来 `read()` 写的是 `input.value.trim() || null`，于是「留空确定」和
    「点取消」都 resolve `null`。调用方顺手写的 `if (due === null) return;`
    （本意是「取消就别记了」）把老实留空跳过的用户一起挡在门外 ——
    **整笔账静默丢掉，连个提示都没有**。
    - 只想拦「取消」→ 必须写 `if (x === null) return;`（不能写 `if (!x)`）
    - **必填项 → 用 `required: true`**，让弹窗自己就地提示，
      别指望调用方 `return`（那是「点了没反应」，用户更懵）
    - ⚠️ 数值型弹窗**尤其危险**：留空 → `Number('')` = **0**。
      「设置当前余额 / 对账 / 金价 / 每月扣款 / 期初余额」都因此加上了 `required` ——
      清空输入框会把余额或净资产**悄悄清零**，比报错可怕得多。
    - 回归：`npm run verify:skip`（21 项，走真实 UI 点弹窗）。
      已负向验证：把 `read()` 改回 `|| null`，第 1 组立刻变红（期望 2 条 / 实际 1 条）。

27. **`toast()` 永远不许渲染成空 / `undefined` / `[object Object]`。**
    调用方大量写 `toast(err.message, 'error')`，但 `err.message` **不保证是字符串**：
    Capacitor 插件和 `DOMException` 抛的不是 Error；`new Error()` 的 message 默认是**空串**。
    结果是**一个空白气泡** —— 看起来就是「点了没反应」，比报错还糟。
    已在 `utils/dom.js` 里按 type 兜底（`error` → 「操作失败，请重试」）。
    🔴 拒绝值**不能**直接 `String(reason)`：`{code:42}` → `[object Object]`。
    只有 `instanceof Error` 或字符串才给用户看。
28. **异步点击处理器抛错必须有人兜。** 界面大量 `onclick: async () => {}`，
    里面某步抛错又没被就地 catch 时，浏览器只记一次 unhandledrejection，
    **界面什么都不发生**。`main.js` 已加 `unhandledrejection` + `error` 两个全局兜底。
    `error` 处理器要用 `if (e.target && e.target !== window) return;` 过滤资源加载失败。
29. **测全局兜底处理器必须用「同源内联脚本」抛错，不能用 `page.evaluate`。**
    🔴 Chrome 把 `evaluate` 的代码当成**另一个源**，抛出的错误会被**脱敏**：
    `e.error === null`、`e.message === 'Script error.'`。用它测会得到**假阴性**
    （处理器明明好的，只是事件里根本没有 error 对象）。踩过：查了三轮才定位。
    正确做法见 `tools/verify_skip.mjs` 第 7 组。
    ⚠️ 顺带纠正一个误判：**`unhandledrejection` 在 headless 下是正常派发的**，
    之前测不出来纯粹是上面这个脱敏问题，别以为「headless 不支持」。

    UI 文案同理 —— 用户明确不喜欢解释性语句（红线 18）。
    ⚠️ 但「说明页 / 使用说明」是用户主动打开的地方，那里该写清楚；

31. **自定义键盘：用 `inputmode="none"` 压掉系统键盘，但别把 `<input>` 换成 `div`。**
    `inputmode="none"` 只关软键盘，元素仍是真输入框 —— 桌面物理键盘、Puppeteer 的
    `page.type()` 照常能用，**不需要开测试后门**。
    🔴 **按键盘键绝不能触发整页 `render()`** —— 会销毁输入焦点。
    数字键只改草稿值 + 就地更新 `dataset` / `input.value`；分类、收支、日期、账户键才可以重渲染。
    键盘格用**显式 `gridArea`**，不要靠自动排布（有跨行键时自动流会把格子挤乱）。
    `normalizeAmount()` 必须是键盘与手输**共用**的规范化函数，否则两条路径产出会不一致。
32. **「让表单底部可见」不要靠底部撑高 spacer —— 那是反效果。**
    ⚠️ **v1.13.5 起「记一笔」改成 `position: fixed` 的底部浮层，
    下面这整套「页面滚动」的推导对它已经作废**（见红线 37），
    但**结论本身对别的内联表单仍然成立**，别照搬也别删。
    滚动被钳住时 `scrollTop = max = A + F + B − clientHeight`，
    表单底边落在 `clientHeight − B ≤ clientHeight`，**底部本来必然可见**；
    唯一装不下的情况是 `F > clientHeight − 8`，撑高也救不了。
    加 spacer 反而把「钳住」分支翻成「顶部对齐」，把底部推出屏幕。
    踩过：`记一笔` 表单在 640 高视口里金额框跑到 −150px；五个高度 A/B 实测证明
    有没有 spacer 键盘可见性**完全一样**。正解是按 `getBoundingClientRect` 算 `topInRoot`，
    `scrollTop = min(topInRoot - 8, max)`。
    ⚠️ **`scrollHeight` 会被钳到 `clientHeight`**（内容比视口短时两者相等），
    用它减 `topInRoot` 去推「下方还有多少」会**多算**。
    （与红线 23 同源：位置一律用 `getBoundingClientRect` 算，不要用 `offsetTop`。）
33. **给模型加字段后，必须检查 `normalizeXxx()` 的字段白名单。**
    这类函数常写成「手挑几个字段返回新对象」，新加的字段会被**静默丢掉**，
    而且**只在「存一次再读一次」之后才现形** —— 直接用 `add()` 测不出来。
    必须补 `fromRecord(toRecord())` 往返断言。踩过：`AccountEntry.ledgerId`
    往返后消失，导致「记账挂账」在重进页面后凭空脱钩。
    另：`entries` 按日期排序，`push` 后取 `at(-1)` 是错的，要用 `addXxx()` 的**返回值**。
34. **`LedgerEntry.account_id` 的语义是「这行从账户页镜像过来」，不要拿它当挂账字段。**
    它驱动 `fromAccount`、「来自账户 · 充值」标签、以及 `openItemMenu` 的只读守卫；
    复用它会让用户**改不了自己的记账条目**。
    记账 ↔ 账户的挂账关系存在**账户那一侧**：`account.entries[i].ledgerId === entry.id`。
    🔴 删除顺序：**先撤挂账、再删记账** —— 最坏是「看得见、可修」的不一致，
    而不是「看不见、但一直在算」的幽灵扣款。
    编辑表单必须把已有挂账**读回**草稿，否则保存一次就静默抹掉扣款。
    🔴 **两套字段是「不对称」的，别记混**（我按错的那套断言，假红过一次）：
    · **记账页挂账户**（v1.13.5 消费账户）→ 关系在**账户流水**的 `ledgerId` 上；
    · **账户页镜像到记账**（v1.7.0 充值）→ 关系在**记账行**的
      `accountId` + `accountEntryId` 上。`_unmirrorFromLedger()` 靠的就是后者。
35. **`LedgerEntry.direction` 只认 `'expense'` / `'income'`，写别的会被静默归到支出。**
    `new LedgerEntry({ direction: 'in' })` 不报错 —— 它会 `direction === INCOME ? INCOME : EXPENSE`
    直接落到 `expense`，连分类也回退成「其他支出」。
    踩过：给截图脚本播种数据写 `direction: 'in'`，图表上凭空多出 3000 元**支出**才发现。
    ⚠️ 别一刀切全局替换：`Loan` 那套模型的借贷方向**确实**是 `'in'` / `'out'`，
    `asset_test.mjs` / `verify_assets.mjs` 里的用法是对的，不要动。
36. **金额有两种显示格式，别混用。**
    - `money()` → `¥1,234.50`：汇总卡、账户余额、预算这类「要看清具体数额」的地方。
    - `amountShort()` / `signedAmount()` → `42.5` / `-42.5` / `+500`：
      流水明细这类「一屏几十个数字」的地方，去币号、去千分位、去无意义小数尾巴。
    🔴 短格式**有损**，只能显示，不能拿去做算术（算术用 `round2()`）。
    🔴 `signedAmount(n, isExpense)` 的符号来自**第二个参数**，不是数字正负 ——
    库里 `amount` 恒为正数、方向另存 `direction`；按 `v < 0` 判断会让支出显示成 `+42.5`。
37. **「记一笔」是 `position: fixed` 的底部浮层，不是页面里的一段。**（用户 2026-09-23 第 1 条）
    生命周期全在 `ledger_view.js` 的 `openForm` / `openSheet` / `closeSheet` / `cancelForm`。
    - 🔴 浮层必须 `pushOverlay()` 登记、dismiss 走 `cancelForm()`，**绝不能 `overlay.remove()`**（红线 13）。
    - 🔴 **Esc 要调 `dismissTopOverlay()`，不能直接 `cancelForm()`** ——
      浮层上还会叠一层 actionSheet（选账户 / 选日期），那时 Esc 该先关上面那层。
      监听挂 `document`，`closeSheet()` 里必须 `removeEventListener`。
    - 🔴 **`openSheet()` 里 `const keep = draft; if (sheet) closeSheet(); draft = keep;`**
      —— `closeSheet()` 会清掉 draft，而这里是「换一层」不是取消。漏了它，
      连点两次「记一笔」第二层就是空表单。
    - 🔴 **`openForm` 是 async，必须用序号作废抢跑**：编辑旧账要先 await
      `findLedgerLinks`，这段空档里用户取消 → `draft` 变 null → await 一恢复
      照样读 `draft.direction` → **TypeError + 未处理 rejection**。
      `closeSheet()` 里 `formSeq += 1`，await 后 `if (seq !== formSeq || !draft) return;`。
    - ⚠️ 子页签切换要把浮层一起收掉（`record_screen.js` 的 `switchTab()` 调 `ctx.closeModal?.()`）——
      `paintBody()` 只换子视图，挂在 `document.body` 上的浮层会活下来变孤儿。
38. **有「两道保险」的地方，测试要各补一条只经过其中一道的用例。**
    否则你以为钉住了，其实钉了个寂寞 —— 单独拆掉任何一道都还是绿的。
    踩过：转账「只镜像转入侧」有两道保险（`transfer()` 只镜像 in +
    `flowToLedger()` 对 out 返回 null）。逐个负向验证发现：
    **拆掉任何一道，那条「当月收入不是 400」都照样绿**（两道都拆才红）。
    补法：新增一组走「账户消费」这条**只经过 `flowToLedger`** 的真实路径，
    再负向验证 → 立刻 4 条红。
    👉 通用的负向验证纪律：**改坏 → 确认变红 → 改回**。只跑绿不算数。
39. **高度尺子用 `dvh` 不用 `vh`**（`vh` 量的是**大视口**，地址栏一露浮层顶就被顶出屏幕，
    且此时 `scrollHeight == clientHeight`，**滚都滚不到**）。
    写法**旧值在前、新值在后**：`max-height:92vh;` → `max-height:92dvh;`（顺序反了等于没写）。
    全站四处同一把尺子：`.led-form` / `.qsheet` / `.input--multiline` / **`body`**
    （`body` 最隐蔽：`min-height:100vh` + `#phone{height:100%}` → 底部导航条被挤出屏幕）。
    ⚠️ **先量绝对高度再改尺子**：「装不下」常是「本来就超了」+「尺子错了」两层叠加。
    ⚠️ headless 里 `100dvh === 100vh` → **渲染断言是假绿**，只能读 CSS 源码断言
    （钉「有旧值 + 有新值 + **新值在后**」；⚠️ 同一选择器可能有多块，`body` 就有两块）。
    👉 `topics/路由与记录页.md` §五
40. **曲线平滑（Catmull-Rom → 贝塞尔）的控制点必须夹到绘图带内** ——
    过冲量 ≈ **相邻落差 / 6**，谷底会沉到基线以下（看着像「负支出」）。
    🔴 配套负向验证必须有**够极端**的种子数据：`[820,1460,640,1980,910,306.85]` 只拱 0.5px
    → 删掉 `clampY` 照样全绿（假阳性）；换 `[900,2400,120,200,1500,600]` 才顶得出来。
    阈值钉**实测值**（不夹 13.7/104.8、夹住 14.0/100.6 → `>=13.9` / `<=101`）。
    ⚠️ `addLedgerEntry` 拒 `amount <= 0`，不能塞 0 去人为造贴基线谷底。
    👉 `topics/路由与记录页.md` §六
41. **`scroll-behavior: smooth` 的容器里，不要用坐标点击（`page.click(sel)`）。**
    Puppeteer 会先滚动到元素，但**坐标是在动画开始前算的** ——
    点下去落在别的地方，表现为「弹层没出来」这种莫名的超时。
    用 `await page.evaluate(() => document.querySelector(sel)?.click())`。
    （与红线 15 同源：smooth 滚动下**任何**按坐标的动作都不可靠。）
42. **升级后手机要「刷新两次」才看到新版本** —— 回答「更新装上了没有」先讲这句。
    SW 是「导航**网络优先** + 静态资源**缓存优先 + 后台更新**」：**第 1 次打开**由**旧 SW**
    控制，HTML 是新的但 JS/CSS 走旧缓存（连「设置 → 关于」那行版本号也旧，`version.js`
    同样缓存优先）；同一次打开后台装好新 SW，**第 2 次打开**才是新版。
    ⚠️ 别把用户引导到「升级失败了」这个结论上。
    👉 验证方法与细节：`topics/发布与PWA.md`
43. **流水列表「一天一组」**：组头报两组小计（`支出 22.5 · 收入 500`），
    但**只有一边有就只报一边** —— 不补「收入 0」，零值小计是纯噪音。
    别退回「日期 → 收支方向」两级分组（同一天会裂成上下两块，看着像两天）。
    `.led-day__head` 要 `flex-wrap: wrap`，且「方向 + 数字」必须包成 `.led-day__sum`
    （否则窄屏换行会把「支出」和「385」拆到两行）；组内**不按方向二次排序**。
    ⚠️ 组头里小计的**标签顺序**（支出在前）跟**行的顺序**是两回事，别混成一条规则。
    🔴 回归断言取数组元素一律用 `?.` —— 写 `.sums[1].total` 会让脚本在被测代码回归时
    **抛异常退出**，后面几十条断言一条不跑（踩过：只报 3 条红就崩；改 `?.` 后完整报出 8 条）。
    👉 `topics/路由与记录页.md` §七
44. **账户之间的转账不计入收入，一条都不进记账总账。**（用户 2026-09-24
    「转账不计入收入，因为，在钱入账的时候已经计算过了的」）
    钱只是在自己名下的两张卡之间挪，总资产分文未变；那笔钱**首次充值进来**时
    记账页已经算过一次收入，转账再算一次就是同一笔钱算两遍
    （与 v1.9.0「账户消费不镜像」同一类错误）。
    - 判据是账户流水的 **`linkedAccountId`** —— **只有 `transfer()` 会写它**，
      外部充值（`recharge`）和每月扣款（`runDueRecurring`）都不写。
    - ⚠️ 拦新的不够，**旧数据也要清**：`purgeTransferLedgerMirrors()`（kv 标记
      `ledger_transfer_mirror_purged_v1137`，在记账页 / 账户页各调一次）。
      它**只删记账侧镜像，绝不碰账户流水** —— 那是两个账户余额的事实依据。
      （别走 `unlinkLedgerEverywhere`：那个是「撤挂账」，会把账户流水一起删掉。）
    - ⚠️ 清理的判定**不能只看 `category === 'acct_in'`** —— 外部充值镜像也是这个分类，
      那是用户**要**的，删了就把收入删没了。要顺着 `accountId` + `accountEntryId`
      回查账户流水有没有 `linkedAccountId`。
    👉 `topics/账户与对账.md`

45. **备份导入会重发所有账户 id，凡是存着「整数 id」的字段都必须跟着重映射。**
    `importJSON()` 要处理三个：`checkin_logs.checkin_id`、`ledger.accountId`、
    **`accounts.entries[].linkedAccountId`**（最后一个 2026-09-24 才补上）。

    - 🔴 找不到对方账户时**保持原样、别清空** —— 那个字段同时是 `isTransferLeg()`
      的判据（见 44），清掉会让转账被当成「外部充值」重新算进收入，又变成双计。
    - ⚠️ **必须用 `merge: true` 测**：替换模式下自增从头发号、旧 id 恰好还对得上，

46. **底部悬浮 dock 的真实占位比 `--nav-h` 大。**
    dock 是 `bottom: 8px` + `height: 66px`，中央那枚 `.bottom-nav__fab`
    还向上**跨出 dock 上沿 20px** → 真正被占住的区域到 **94px**。
    而 `.record-body-host > .acct-view` 的 `padding-bottom` 原本是
    `calc(var(--nav-h) + 22px)` = 80px < 94px，于是页面**最后一个元素**
    滚到底时正好被压住 —— 用户 2026-10-13 反馈账户页「账户明细」不好被发现，
    就是这个（它当时还只是一行 13px 的裸文字）。
    现在用 `calc(var(--nav-h) + 46px)` = 104px。
    - ⚠️ 断言要**同时**量两条：「不与 dock 重叠」+「留够呼吸空间（>= 24px）」。
      只把元素本身做大（比如换成卡片）能骗过前者 —— 实测只改卡片、底部留白不动，
      不重叠那条照样绿，只有呼吸空间那条会红。
    - 👉 回归：`npm run verify:acctdetail` 第 1 组。

47. **「定宽 + 数字」是换行陷阱。**
    `.acct-flow__date` 原本写 `width: 36px`。在 Windows 的 Segoe UI 下
    "10-10" 只有 **31.95px**，塞得进；到了手机上（字体度量更宽 / 开了字体放大）
    同样的 "10-10" 超过 36px 就**折成两行**，行高从 19.4px 变 46.5px，
    整块账户流水看起来被拉得很长（用户 2026-10-13 说「时间竖着排版的」）。
    正解：**日期这类定长串一律 `white-space: nowrap` + 不定宽**
    （`min-width` 只用来保证多行左边缘对齐）。
    - 🔴 **回归里只按本机默认字体量「占几行」是假绿**：把 CSS 改回 `width: 36px`
      在本机照样全绿。必须再**放大一轮字号**（注入 `.acct-flow { font-size: 15px }`）
      才抓得住 —— 那复现的正是「文字比定宽盒子宽」这个几何。
    - 👉 回归：`npm run verify:acctdetail` 第 3 组。

48. **底部抽屉（`.sheet`）必须限高 + 只有列表滚动。**
    `actionSheet()` 的选项原本是 `.sheet` 的**直接子节点**，而 `.sheet`
    既没有 `max-height` 也不滚动 —— 选项一多（「账户 → 全部流水」最多 30 条
    × 46px ≈ 1380px）整张面板就长到屏幕之外：顶部被裁掉、且**怎么滑都不动**，
    「取消」也被顶到屏幕外（用户 2026-10-13 反馈「显示不完全，不能滚动查看」）。
    正解：`.sheet` 加 `display: flex; flex-direction: column;
    max-height: calc(100dvh - 28px)`（旧值 `100vh` 在前，见 39），
    选项包进 `.sheet__list { flex: 1 1 auto; min-height: 0; overflow-y: auto }`，
    标题 / 说明 / `.sheet__item--cancel` 一律 `flex-shrink: 0`。
    - ⚠️ `min-height: 0` 不能省：flex 子项默认 `min-height: auto` 会拒绝收缩，
      列表会把整张面板顶高，`max-height` 形同虚设。
    - ⚠️ 别顺手 `slice(0, 30)` 截断列表却把标题写成「共 N 笔」—— 后几笔会变成
      **看不到、也删不掉**。
    - 👉 回归：`npm run verify:acctdetail` 第 2 组。

49. **写死日期的 E2E 会「馊」—— 播种日期必须跟着当前月/周走。**
    记账页默认只看**本月**（`ledger_view.js`：`let month = monthKey(new Date())`），
    而 `verify_ledger_form` / `verify_ledger_list` / `verify_account_transfer`
    都把播种日期写死成 `2026-09-xx`。2026-10-13（10 月）实测，**代码一行没改**：
    - `ledgerform` 直接**崩在** `No element found for selector: .led-item`；
    - `ledgerlist` **14 红**（「流水列表已渲染」等一片）；
    - `transfer` **3 红**（`当月收入` 期望 127 / 实际 50 —— 那笔 77 落在 9 月，看不见）。
    改成跟着当前月算：`const ym = \`${y}-${mm}\``，日期用 `${ym}-18/19/20`。
    - ⚠️ `DatabaseService.getLedgerByMonth()` 只按 `date.startsWith(month)` 过滤、
      **没有上界** —— 所以用固定的 18/19/20 号是安全的（月初跑也不会漏），
      不必刻意避开「今天还没到的那几天」。
    - ⚠️ 这类「馊掉」的表现是**崩溃 + 整片红**，最容易被当成真回归去查半天。
      看到「昨天还全绿、今天没改代码就红了」，先查**日期**。
    - 👉 同族问题：`verify_account_detail` 的流水日期也从「本月 5 号往前倒推」算。

50. **`scroll-behavior: smooth` 的容器里「滚到底再量坐标」必须轮询 `scrollTop` 稳定。**
    `verify_assets` 的「滚到底后折叠开关不被底部导航挡住」原来写 `scrollTop =
    scrollHeight` 然后 `wait(600)`。单跑够，但 14 个脚本连着跑、机器一忙就量到
    **动画中途** —— 实测报「开关底 851px / dock 顶 828px」，看着像真 bug，
    等它停稳后其实是 **796 / 828**（32px 余量，完全正常）。
    - 🔴 **假红比假绿更费时间**：它会让人去查一个**不存在的回归**。
    - 👉 写法见 `verify_ledger_form.mjs` 的 `stableScrollTop()`：连续 5 次读数相同才算稳。
    - 👉 相关：红线条 15（同一根 `smooth` 的另一个坑）、41（smooth 下别用坐标点击）。

51. **解析子进程 / CLI 输出前先剥 ANSI 颜色码；判断通过与否只认「总结行」。**
    `tools/verify_all.mjs` 汇总时用 `全部通过[^0-9]{0,6}(\d+)项` 抠数字，结果
    `acctdetail` 明明打印了 `全部通过（34 项）`，汇总表却报「没认出总结行」。
    原因是那一行是 `\x1b[32m全部通过\x1b[0m（34 项）` —— **重置码 `\x1b[0m` 自带一个数字 `0`**，
    `[^0-9]` 匹配不了它。修法：`s.replace(/\x1b\[[0-9;]*m/g, '')` 之后再解析。
    - 🔴 **这些回归脚本断言失败时照样 `exit 0`**（`check()` 只累加计数器）→ **退出码不可信**。
    - 🔴 `grep -cE '^\s+✗'` 也会**漏报**：失败项最后会再汇总成 `  · 项目名` 列表（不带 ✗）。
      → **grep 也不可信，只认总结行**。
    - 👉 全量跑用 **`npm run verify:all`**：顺序跑完 `package.json` 里所有 `verify:*`，
      解析总结行给出真总表，脚本之间留 1.2s 间隔（避免互相抢资源），
      且**只对「没认出总结行」（= 没跑完）重跑一次**，真正断言失败的绝不重试。
    - ⚠️ `verify_all.mjs` 必须**排除自己**（`verify:all` 也是 `verify:` 开头），否则无限递归。
