# PWA 发布纪律

- ⚠️ **改 `web/` 下任何文件后，必须把 `package.json` 的 version 加 1 并运行 `npm run pwa`**
  （同步 `sw.js` 的 `VERSION` 与 `PRECACHE`，自动扫盘）。
  **不这么做，手机上已装的版本会一直吃旧缓存 —— 改了代码也看不到效果。**
  🔴 **SW 的缓存键是 `v<package.json version>`，不是内容哈希** ——
  所以「只改了内容没改版本」= 用户永远看不到新内容。
  同理安卓端：`build.gradle` 从 `package.json` 读 versionName/versionCode，
  不升版本会导致新包与旧包 versionCode 相同而**装不上去**。
- **7 张图标**，`build_pwa.mjs` 的 `ICONS` 数组守着齐全性。
  **预缓存条数以 `npm run pwa` 的实际输出为准，不要手写死数。**
- ⚠️ **precache 扫盘会把 `tools/*.png` 之类调试产物一起收进去** —— 跑完扫一眼 `PRECACHE`。
- ⚠️ **`verify_pwa.mjs` 不在 `run_all.mjs` 的套件里** ——
  更名这类改动跑全量测试**发现不了它**，必须单独跑一次。
- **`serve.mjs` 默认绑 `0.0.0.0`**（手机要连），读的是 **argv[3]**：
  只想本机要写全 `node tools/serve.mjs 8080 local`。
  ⚠️ 用 `(cmd &)` 后台起服务会随 shell 退出被杀 —— **用工具的 `run_in_background`**。
- ✅ **手机端能力（v1.12.0 起已补齐，别再写成「不可用」）**：
  图片 OCR 走**设备端 ML Kit 中文离线识别**（图片不出手机）；
  本地提醒走**系统闹钟**（关掉应用也会响、开机自动恢复）。
  注意系统仍会杀后台，所以提醒**不是**在应用内轮询实现的 —— 改这块要清楚这一点。
- ⚠️ **用户会问「安装包在哪 / 怎么装」** —— **APK 已经有了**：
  `dist/周周记-v1.13.0.apk`（27.1 MB，自有密钥正式签名），拷进手机点击安装即可。
  ⚠️ 但**源码已到 v1.13.5**（2026-09-23 起），`dist/` 里最新仍是 v1.13.0 ——
  按用户要求先不出包，所以这个文件名是**准确的、不是笔误**。
  **必须提醒先卸载 debug 版**（签名不同，无法覆盖安装，卸载会清数据）。
  改代码后要重新出包，看 `备份与安卓.md`「实际构建记录」（工具链已装在
  `D:\android-toolchain`，但有 4 个坑必须知道）。
  **PWA 仍是零安装的备选路径**（手机 Chrome 打开局域网地址 → ⋮ →「添加到主屏幕」）。

## 🔴 SW 更新要「刷新两次」才看到新版本（2026-09-23 查证）

策略组合：`install` 里 `skipWaiting()` + `activate` 里 `clients.claim()` +
导航请求**网络优先** + 静态资源**缓存优先 + 后台更新**。
这套组合是对的，但它的**必然结果**是：

| | 谁在控制 | 导航（HTML） | 静态资源（JS/CSS） | 用户看到 |
|---|---|---|---|---|
| **第 1 次打开** | 旧 SW | 网络优先 → **新 HTML** | 缓存优先 → **旧 JS/CSS** | **旧版本** |
| 同一次打开的后台 | 新 SW 装好 → 接管 → 删旧缓存 | — | — | — |
| **第 2 次打开** | 新 SW | 网络优先 → 新 HTML | 新缓存 → **新 JS/CSS** | **新版本** |

所以**升级后第一次打开仍是旧的**（连「设置 → 关于」那行版本号也还是旧的，
因为 `version.js` 也走缓存优先）—— **必须再刷新一次**。
如果用户第一次打开后立刻关掉（新 SW 还没装完），可能要**第三次**才生效。

👉 **回答「更新装上了没有」时，先说「多刷新一两次」，再说别的。**
别让用户以为升级失败了。

### 怎么证实的（结论别靠推理，跑一遍）

往**版本缓存**里手工塞一份假的 `js/version.js`（`APP_VERSION = '9.9.9'`），
然后：

- **同页直接 `fetch('./js/version.js')`（不 reload）→ 拿到 `9.9.9`** ✅
  证实「缓存优先会把缓存里的旧内容发出去」。
- **reload 之后再 fetch → 拿到真版本** —— 因为上一步的**后台更新**已经把
  缓存悄悄改回真文件了（`cache.put(req, res.clone())` 在 `return cached` **之前**就发起了）。

⚠️ 第一步最容易做错：`cache.put` 用**相对路径**会因 base 不同而对不上，
用 `new URL('./js/version.js', location.href).href` 拿**绝对 URL** 再 put。
验证时也要记得 `cache.match(abs)` 回读一次，确认真塞进去了。

⚠️ 想改成「一次打开就生效」，得加 `controllerchange` 监听 + 一次
**带守卫的** `location.reload()`（`hadController` 判首次安装、
`refreshing` 防循环）。目前**没加** —— 现有机制是标准做法且工作正常，
加自动刷新属于改行为，要用户点头再做。

## 预缓存清单：排除开发用页面靠**代码**，不靠肉眼

扫盘是按**扩展名**收的（`.js` / `.css` / `.html` / `.webmanifest` / `.png`），
所以任何扔进 `web/` 的开发用 `.html` 都会被悄悄收进离线缓存。
以前的做法是「跑完 `npm run pwa` 自己扫一眼 `PRECACHE`」——**容易漏**。

现在 `tools/build_pwa.mjs` 里有 `NO_PRECACHE` 集合：

```js
const NO_PRECACHE = new Set([
  'sw.js',              // 由浏览器自己管理
  'logo-preview.html',  // 品牌资产预览页，开发时看的
]);
```

⚠️ 排在这里**不代表访问不了**：SW 静态分支是「缓存优先 + 后台更新」，
没预缓存就退回网络，首次访问后照样会被缓存 —— 只是不**主动**下载。

`verify:pwa` 有两条断言钉住（**25 项**，原来 23）：
「开发用页面没被预缓存」+「预缓存里的 `.html` 只有 index.html 一个」。
已负向验证：手工把 `logo-preview.html` 塞回 `PRECACHE` → 恰好那 2 条红。

## 🔴 升版本号时要同步的地方（漏一处就是文档漂移）

改完 `web/` 升 version 后，这几处**必须一起改**，否则文档会指向不存在的文件或旧数字：

| 位置 | 改什么 |
|---|---|
| `package.json` | `version`（源头） |
| `web/sw.js` | `VERSION` —— **由 `npm run pwa` 自动写，别手改** |
| `README.md` | 顶部横幅的 APK 文件名与体积；「产物」表的文件名 + versionName/versionCode；**版本表加一行**；文件树的 `dist/` 与 `tests/` 清单 |
| `06_安卓安装与部署.md` | 顶部横幅；「实测结果」表的体积/versionName/versionCode；2.4 的安装命令与 APK 路径；4. 自检清单里的套件数 |
| `测试记录.md` | 头部「版本 / 测试日期」；**新加一节**（格式：需求 → 改动 → 验证结果 → 本轮踩的坑） |
| `dist/` | 新包拷进来；**旧包挪进 `dist/历史版本/`**（两个 release 包并存容易装错） |

> `00_` ~ `05_` 那六个 md 是**最初的需求/规格文档**（不随版本变），不用动。
