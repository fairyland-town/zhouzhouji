# 解析器架构（通知文本 → 结构化活动）

> 从 `MEMORY.md` 拆出。改 `web/js/utils/` 下任何 parser、`regex_patterns.js`、
  `category_*` 之前先读完本文。详细规则与边界用例见 `README.md`「解析器」章。

## 硬约束

- parser 分离：`Title / Time / Location / Category / Speaker / Event`。
  **只用规则 + 正则，禁止引入任何在线大模型**（用户明确要求，不消耗 token）。
- 🔴 **规则优先级远比正则本身重要**（同一教训出现四次）。**先排优先级，再写正则。**
- **「步骤顺序」和「正则捕获组编号」都是契约**：加高优先级规则时要确认
  (a) 不抢后续步骤输入（加**上下文约束**）；(b) 没改变已有捕获组语义（用 `(?:…)`）。
- **扩大某类覆盖面时必须回头检查边界**（合并分类 = 要吃更多词 = 原本被其他类接住的
  边界情况会涌进来）。加否决词表最省事。
- **要校验用户原始输入，就不能校验已被规范化的字段**（构造函数会把脏日期格式化成今天），
  必须另留 `rawDate`（并用 Date 回环检测 `2026-02-31`）。
- **识别「哪一类」和「是什么」是两件事**，不能让一个解析器兼任。
- **「有值」不等于「有意义」**：剥完剩下的还成立吗（`NOTE_RESIDUE` / `isMeaninglessNote`）。
- **守卫的语义边界要跟调用场景对齐**：行尾数字当价格这条兜底
  **不能复用 `isAmountLike`** —— 后者定位是「强候选」，会把它滤掉。

## 分类系统（3 类）

`academic` / `job` / `other`。学术 = 会议 + 报告 + 讲座 + 论坛 + 沙龙 + 研讨会；
就业 = 宣讲 + 招聘 + 双选 + 实习 + 校招。

- **学术类的「活动名称」就是会议名 / 报告题目**，无独立会议名字段
  （`meetingName` 已废弃，别加回来）。学术卡片只多显示一行「报告人」。
- **判定顺序（不可调换）**：用户 hint → **`NON_ACADEMIC_BLOCK` 内部事务词否决**
  （否则「教学工作研讨会」会被带进学术）→ 强关键词命中 → 关键词打分 → 兜底 other。
- 地点字段**不参与分类判定**（否则「学术报告厅」会污染全文）。
  旧 id 迁移表：`LEGACY_CATEGORY_MAP`。

## 金额三铁律

1. 剥离顺序**先剥带单位金额再剥裸数字**（反了会残留「元」）。
2. 「取第一个 / 取最大数字」都是错的，要按「像不像金额」定优先级。
3. **认不出时宁可留空 + 提示，绝不猜。**

> **任何依赖「谁先出现」的解析都是脆的**（OCR 行序不稳定）。

## 手输日期解析（v1.13.5）

用户 2026-09-22：「所有填写日期的时候不应该只有一种格式 2026-10-08。
2026.3.8 这种以及 2026.09.08 都可以」。

- 统一入口 `parseDateInput(raw)`（`web/js/utils/date_utils.js`）→ 规范化 `YYYY-MM-DD`，
  看不懂返回 `null`（空串也返回 `null`，**调用方自己区分「跳过」和「取消」**）。
- 放行分隔符：`-` `/` `.` `年/月/日`，月/日可不补零，尾部 `日` / `号` 可选。
- 正则 `PATTERNS.DATE_INPUT` —— **锚定首尾**。
  ⚠️ 别复用 `PATTERNS.FULL_DATE`：那是「在一整段通知里捞日期」，不锚定是它的本分；
  拿来校验输入会让「2026-10-08 随便写点什么」被判成合法。
- 🔴 **必须回读校验**：正则只保证「长得像」。`2026-02-31` 合规，但
  `new Date(2026, 1, 31)` 会被 JS **静默滚到 3 月 3 日**，把用户没输入过的日期存进库。
  做法：构造 Date 后反读 `getFullYear/getMonth/getDate`，三个都对上才算数。
- 接入点：借出「约定哪天还」、定期「到期日」、待办「截止日期」。
  （记账页日期走原生 `<input type="date">`，本来就是 ISO，不用管。）
- 期望值：`tests/run_tests.mjs` 的「手输日期解析」两组（26 项），
  含闰年反向验证（2026-02-29 拒绝 / 2024-02-29 放行）。

## 输入弹窗返回值契约（v1.13.5）

`promptDialog` 返回**三态**，不是布尔：`null` = 取消 / `''` = 明确留空（跳过）/ 其它 = 输入内容。
只拦取消必须写 `if (x === null) return;`；必填项用 `required: true`。
数值型弹窗留空 → `Number('')` = 0，会把余额 / 净资产**悄悄清零**，所以都要 `required`。
详见 `MEMORY.md` 红线 25，回归 `npm run verify:skip`。
