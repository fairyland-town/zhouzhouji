# 测试与调试手段

> 从 `MEMORY.md` 拆出。写/改 `tests/` 或 `tools/verify_*.mjs` 之前先读完本文。

## 一、跑什么

- 一键跑全部：`node tests/run_all.mjs`（**11 套**：单元 / 分类 / 语料 / 记录 / 待办 / 账户 /
  资产 / 本地提醒 / 原生调用链 / OCR / E2E）。
- PWA：`node tools/verify_pwa.mjs`（需先有服务；含**离线重载**）/ `npm run pwa:check`。
- 视觉与专项回归：`tools/verify_glass.mjs`（玻璃令牌 / dock 几何）、`verify_amount_ui.mjs`、
  `verify_account.mjs`、`verify_assets.mjs`、`verify_week_scroll.mjs`、`verify_gestures.mjs`、
  `verify_guide.mjs`、`verify_source_required.mjs`、`verify_nav_icon.mjs`、
  `verify_backup.mjs`、`verify_icons.mjs`。
- ⚠️ **`verify_pwa.mjs` 不在 `run_all.mjs` 的套件里** —— 更名这类改动跑全量测试
  **发现不了它**，必须单独跑一次。
- 🔴 **npm 脚本名和文件名不一样**：`verify_nav_icon.mjs` 对应的脚本是
  **`npm run verify:nav`**（不是 `verify:nav_icon`）。
  完整的 npm 别名：`pwa` / `pwa:check` / `verify:{glass,nav,backup,icons,assets,gestures,pwa}`。
  ⚠️ **`npm run --silent <不存在的脚本>` 会静默无输出**（不是报错），
  用 `| tail` 看结果时极易被误当成「跑过了、没问题」——
  新增脚本后先 `node -e "console.log(Object.keys(require('./package.json').scripts))"` 核对一遍。

## 一·五、原生链路怎么测（没有真机时）

`tests/native_services_test.mjs` —— 装一个假的 `window.Capacitor`，把
`nativePromise(plugin, method, options)` **全部录下来**，逐条断言「插件名 / 方法名 / 参数」。

- **为什么必须单独测**：设备端 OCR 与系统闹钟这两条链路**从来没在真机上跑过**
  （开发机无安卓设备/模拟器）。读插件源码只能证明「插件 API 长这样」，
  **不能证明我们的调用代码产生了正确的调用**。
- **能抓到**：插件名/方法名写错、参数名写错（`path` vs `uri`）、`directory` 值写错、
  两步写盘的顺序错、临时文件没删、增量对账算错（该排的没排 / 不该排的重复排）。
- **抓不到**：插件内部真实行为 —— 那只能靠真机。
- **套路**：`handlers['Plugin.method'] = (options) => 返回值` 逐组重装；
  `callsOf(plugin, method)` 过滤；`freshXxx()` 每组造一个干净实例。
- 🔴 **造「距现在 N 分钟」的测试数据必须显式传时间基准**：
  `ev(id, minutesFromNow, base = Date.now())`，各组开头取一次 `const T0 = Date.now()`。
  否则同一个活动造两次会拿到相差几毫秒的 `startDate`，断言「提前量」随机失败
  （踩过：期望 `…257` / 实际 `…255`，连跑五次才复现）。

## 二、E2E 写法约定

- **断言必须按标签取值，不能用数组下标**（新增字段会破坏下标断言）。
- **需求变更会连带 E2E 断言失效，这是正常的** —— 正确处理是**改断言匹配新需求**，
  而不是把功能改回去迁就测试。
- **UI 动画会同时污染两件事**：① click 坐标不可用；② 布局尺寸读数不稳定。
  收口到 `clickByText` 统一兜住（等非零尺寸 → `sleep(320)` → 真点 / 降级 `el.click()`），
  **不要在调用点各写一遍 sleep**。测量布局前也要 `sleep(900)` 等动画收敛。
- **`page.type(sel, ...)` 在「点击触发整表单重绘」时会抛 `No element found`**
  —— 改用 `page.$eval(sel, el => el.focus())` + `page.keyboard.type(...)`。
- **定位输入框不要用 placeholder**（会把占位文字读进去），用 `data-field` 等稳定属性。
- **`window.__app` 不存在**，调试脚本走真实 UI；切 tab 用
  `document.querySelector('.screen--record').__switchTab('account')`。
- 底部「＋」不直达添加页，E2E 统一收口到 `gotoAddPage(page)`。
- 🔴 **`page.reload()` 后记录页默认落在「打卡」**，不是刚才那个子板块。
  任何「reload 后断言账户页元素」的脚本都必须先重新切到目标子页
  （`verify_assets.mjs` 为此写了 `gotoAccount()`）。**这个坑栽过两次。**
- 🔴 **`scroll-behavior: smooth` 让一切「滚动类」断言天生不稳** ——
  设完 `scrollTop` 再 `sleep(固定值)`，动画时长随机器负载变化，
  实测同一台机器能从 `scrollTop 11/239` 漂到 `238/239`。
  **正确做法：轮询到 `scrollTop` 连续若干帧不变**（`verify` 用 4 帧、上限 2 秒），
  并且**补一条「到底了没有」的断言** —— 否则「没滚到底」会伪装成「布局坏了」。
- 🔴 **写死日期的用例会随机器时间漂移而失败**。
  踩过：用例把活动写在 9/18，机器日期走到 9/22 后 `reload()` 默认显示「本周」（9/21–9/27），
  `.event-card` 合理地不存在 —— 看着像回归，其实是**用例自己过时了**。
  修法是加 `gotoWeekOf(page, rangeText, maxHops)`（配 `parseRangeStart()`）
  让用例**显式翻到目标周**，而不是依赖「默认就是那一周」。
- **测滑动手势要真的派发 `TouchEvent`**（构造 `new Touch({...})` + `touches` 数组），
  不能只调内部函数 —— 否则「定轴」「阻尼」「纵向不翻页」这些行为全都测不到。

## 三、脚本环境坑

- **ESM 不认 `NODE_PATH` 也不能用 Windows 绝对路径**：puppeteer-core 要 `existsSync`
  探测 + `pathToFileURL()` 动态 import —— 新脚本**照抄 `verify_glass.mjs` 开头那段**
  （候选路径含
  `C:/Users/27693/.workbuddy-ai/binaries/node/workspace/node_modules/puppeteer-core/...`）。
- **在浏览器里 `import()` 项目模块要用网页根路径**：
  `await import('/js/services/account_service.js')` 再取 `.default`。
  `AccountService.create()` **内部自行初始化数据库**。
- **`setContent` 出来的页面没有 `file://` 源**，直接引 `file://` 图片会被跨源策略拦掉
  —— 要 `readFileSync().toString('base64')` 内联成 data URL。
- **`Read` 会把视觉相似的小 PNG 判成「未变化」不返回内容** —— 靠放大脚本绕过。
- **量「字形墨水覆盖率」时**：把 `currentColor` 换成黑色即可，
  **绝不能顺手把根节点的 `stroke` 改成 `none`** —— 那会让描边版彻底不渲染（量出 0%）。
  阈值放宽到「实心 > 描边 × 1.6」即可（`stroke-width: 1.9` 本身就占 ~30%）。
- **`page.evaluate` 里 `import()` 项目模块可能失败** —— 改用「克隆真实 DOM 节点到 canvas
  + `img.decode()`」量像素。

## 四、检查脚本自身也会错

- 🔴 **噪声多时先怀疑检查逻辑，别急着改被检查的对象。**
  踩过：PRECACHE 洁净度检查用 `/_/` 想匹配 `_zoom_icons.png`，结果把正常文件名里的
  下划线全匹配了，刷出 30 多条假阳性。**应锚定具体前缀**
  （`shot_` / `zoom_` / `mask_` / `debug` / `tmp`）。
- **写断言前先读实现**（曾把 `stats.count` 当「活跃账户数」）。
- 🔴 **期望值反复调不收敛时，先怀疑模型而不是期望。**
  期望值改到第三次就该停下来，**先写独立真值表脚本钉死期望，再改实现**。
  踩过：让 `runCount` 兼任「补扣上限」，与 `lastRun` 语义重叠，来回震荡多轮。
- 🔴 **console 错误的来源要看 `m.location().url`，不能只看 `m.text()`。**
  资源加载失败的消息文本永远是同一句 `Failed to load resource: net::ERR_XXX`，
  从文本里**分不出是谁在报错**。
  踩过（v1.13.2）：给 `verify_assets.mjs` 加了「进设置页」这一步后，
  末行「无控制台错误」开始假红 —— 设置页会探测本机 OCR 服务
  （`http://127.0.0.1:8765/health`），测试机上没开，浏览器必然抛连接被拒；
  而老过滤条件 `!/OCR/.test(m.text())` **挡不住**（文本里既没「OCR」也没端口号）。
  修法：

  ```js
  const isOcrProbe = (m) => {
    try { return /127\.0\.0\.1:8765/.test(m.location()?.url || ''); } catch { return false; }
  };
  ```

  ⚠️ **改完过滤条件一定要做负向验证**：写个探针脚本把
  `m.location().url` 打出来，确认过滤器**真的命中** ——
  否则你无法区分「过滤生效了」和「这个错误恰好没发生」。
- 🔴 **临时探针脚本别放 `/tmp`**：Git-Bash 里的 `/tmp/x.mjs` 交给 Windows 版 Node
  会被解析成 `D:\tmp\x.mjs` → `Cannot find module`。放项目内 `.debug/`，用完删掉。
  另外 `rm -rf .debug` 偶尔静默不生效，删完用 `ls -d .debug || echo 已清理` 复核一次。
- 🔴 **取数组元素一律用 `?.`，否则被测代码一回归，脚本自己先崩。**
  踩过（v1.13.5 第三轮）：`verify_ledger_list.mjs` 第 2 组写的是
  `day19.sums[1].total`。做负向验证把分组改回「日期 + 方向」时，
  `sums[1]` 变成 `undefined` → `TypeError` → **整个脚本抛异常退出**，
  只报了 3 条红就没了，后面几十条断言一条没跑，**看不到全貌**。
  改成 `day19.sums[1]?.total` 之后，同一个场景完整报出 **8 条红**。
  ⚠️ 这不是「被测代码的错」，是**回归脚本自己的健壮性问题** ——
  回归脚本的职责是「尽可能多地把问题一次报全」，不是「第一个问题就罢工」。
  同理适用于 `arr[0].x`、`find()` 的结果、`querySelector` 的结果。
