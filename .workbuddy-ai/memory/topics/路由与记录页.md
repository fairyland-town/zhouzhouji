# 路由 · 导航 · 记录页

## 一、路由与导航

- 路由：`week | add | confirm | editConfirm | detail | record | settings | guide`。
  **`history` 路由已删除，不要加回来。** 底部导航三项：**周历 / 添加(FAB) / 记录**。
- ⚠️ **底部中央「＋」不直达添加页**，打开「快速记录」抽屉（`widgets/quick_sheet.js`）；
  进添加页要走抽屉下半区「粘贴通知」。E2E 里 `click('.bottom-nav__fab')` 后等
  `.segmented`/`textarea` 的地方**统一收口到 `gotoAddPage(page)`**。
- 「记录」页 = **打卡 / 待办 / 记账 / 账户**（此顺序），子视图在 `screens/record/`。
  分段 4 项后需 `.segmented__item { padding: 0 6px }` 否则换行。
  **E2E 有两处断言写死 tab 顺序**（第 8 组开头 + 8.7 开头），改顺序要同步改。
- **新增视图函数必须是同步的**（返回 `root` 前调用 `render()` 但不 await）——
  `record_screen.js` 的 `paintBody()` 是同步的；最外层导出函数**不要 async**
  （允许 `render().then(...)` 消费深链动作）。
- **抽屉深链**：`ctx.go('record', { tab, action })` 的 `action` 是一次性动作，
  `paintBody()` 包成 `{...ctx, params}` 传下去并立即清空（避免切 tab 重放）。
- 记录页宿主 `.record-body-host` 必须 `flex:1; min-height:0; overflow:hidden`。
- **导航栈是内存里的 `ctx.stack`，不是浏览器 history**（v1.3.0 起有意如此）。
  所以 `webView.canGoBack()` **永远 `false`** —— 这一点是「侧滑返回」功能的前提，见第四节。
- 🔴 **`go(ROOT_ROUTE)` 必须清空 `ctx.stack`**（v1.13.0）。否则
  `week → add → confirm → week` 之后按返回会退回**已经提交过的确认页**。
  另外：**「返回上一页」一律用 `ctx.back()`，不要用 `ctx.go('week')`** ——
  后者是「跳回首页」，不是「返回」，语义不同（v1.13.0 已把 6 个页面统一改过来）。
- **周号已废弃**：不显示「第 N 周」，只显示相对周 + 日期区间。
  `isoWeekNumber()`/`isoWeekYear()` 保留（单元测试在用）但**不要在 UI 里调用**。
  改周相关 UI 跑 E2E 第 1 组（断言 `/第\s*\d+\s*周/` **不匹配**）。

## 二、记录页设计约定

- **打卡**：`checkins` + `checkin_logs`（同项同日唯一，靠复合唯一索引）。两条口径别改坏：
  ① **今天没打卡不算断卡**（`streak()` 从今天或昨天起算）；
  ② **月完成率分母不含未来日期**（否则月初显示 3% 这种失真数字）。
- **记账**：金额**一律存正数**，方向由 `direction` 决定，展示时才拼 `+`/`-`；
  分类必须与方向匹配（收入不能挂「餐饮」）。预算存 `kv`，键 `ledger_budget_YYYY-MM`。
- **一键导入 = 解析 → 预填 → 用户核对 → 保存**，绝不允许识别结果直接入库。
- **账户「充值」的来源必填，「消费」的备注可跳过**（v1.7.2，用户只要求改充值）。
- `promptDialog` 的 **`required` 选项**：空内容点保存**不关窗** + 就地显示 `.modal__hint` 红字。
  **必须做进弹窗内部，不能在调用处写 `if (!note) return`** ——
  它返回 `null` 时「空提交」与「点取消」无法区分，会造成静默失败。

## 三、记录页左右滑动翻板块（v1.13.0）

四个子板块支持左右滑动翻页。**难点不是「怎么翻」，而是「怎么不误伤纵向滚动」** ——
记录页全是可纵向滚动的长列表，无脑 `preventDefault()` 会让页面滑不动。

**先定轴，再拦截**（`installSwipe()`）：

```js
const SWIPE_MIN = 56;   // 松手翻页的最小水平位移
const AXIS_LOCK = 9;    // 判定「这是横向手势」的最小位移
const RUBBER = 0.34;    // 首尾阻尼
const SLIDE_MS = 200;   // 翻页动画时长，与 CSS 一致
```

- `touchstart` 只记起点；`touchmove` 里位移没超过 `AXIS_LOCK` 就**直接 return（不拦）**；
  超过后比较 `|dx|`/`|dy|` 定轴：纵向 → `tracking = false`，**整个手势交还浏览器**；
  横向 → 才 `preventDefault()` 接管。
- 🔴 **必须用 touch 事件，不能用 pointer 事件** —— 只有 touch 能 `preventDefault()`
  （`pointermove` 不可取消），而「定轴后才拦」的前提就是能拦。
- 声明式那层：`.record-body-host, .record-body-host > * { touch-action: pan-y; }`
  🔴 **`touch-action` 不继承** —— 只写容器，子元素照样会被横向拖动带偏。
- 首尾用 `RUBBER` 阻尼回弹；`inHorizontalScroller()` 保证不抢横向滚动条的手势。
- **翻页动画必须两段式 + 强制重排**：当前内容滑出 → 换内容 → 新内容从另一侧滑入。
  中间要 `void bodyHost.offsetWidth`，否则浏览器把「设 transition」与「设 transform」
  合并成一次样式变更，结果是**跳变而不是滑动**。
- 根节点上挂了 `el.__tabIndex` / `el.__tabCount`，供返回键判断当前板块。

## 四、安卓侧滑返回（v1.13.0）

**根因在 `@capacitor/app` 的 `AppPlugin.java:46-58`**：

- JS **注册过** `backButton` 监听 → 原生把事件交给 JS，**自己什么都不做**；
- **没注册** → `canGoBack() ? webView.goBack() : (什么都不做)`，
  「什么都不做」落到 Activity 默认行为 = **退出 App**。

本项目导航栈在内存里，`canGoBack()` 恒为 `false` → 第一次滑不做事、第二次滑退出。
这就是用户说的「滑两次直接退出软件」。

**零构建项目不能 `import` 插件的 npm JS**，但注入的 `window.Capacitor` 上有 `addListener`。
于是 `native_bridge.onNativeEvent(plugin, event, handler)` 直接用它注册 ——
**不需要打包任何插件 JS**。注册监听后原生就完全不再自动退出。

`handleBack()` 是四级优先级阶梯，每级 `return true` 表示已消费：

```js
if (dismissTopOverlay()) return true;                      // ① 先关浮层
const rec = document.querySelector('.screen--record');
if (rec?.__tabIndex?.() > 0) { rec.__switchTab('checkin'); return true; }  // ② 记录页退回第一个板块
if (ctx.route !== ROOT_ROUTE) { ctx.back(); return true; } // ③ 退一层路由
// ④ 两步退出：2 秒内第二次才真退，第一次只 toast
```

**浮层栈**（`dom.js` 的 `pushOverlay` / `popOverlay` / `dismissTopOverlay`）：
`confirmDialog` / `actionSheet` / `promptDialog` / `quick_sheet` 都要注册进来。

> 🔴 **`dismiss` 必须走各自正常的取消路径，绝不能 `overlay.remove()`。**
> 浮层背后通常有一个 `await` 着的 Promise，直接摘 DOM 会让它**永不 resolve**，
> 调用方静默挂死 —— 不报错，只表现为「点了没反应」。
> 另外 `closeModal()` 里要 `resetOverlayStack()`，否则栈里会残留已销毁的浮层。

浏览器里可以用 `window.__cwBack()` 等价触发（`verify_gestures.mjs` 就靠它测）。

### 高度预算（v1.13.5 第二轮，用户 2026-09-23 第 1 条）

用户原话：「记一笔的那个界面调整一下，要不然数字键盘会要自己上下滑动才可以点击下面的内容」。

**两层根因，只修一层不够：**

1. **绝对高度本来就超了。** 探针实测各段：
   head 34 + dir 25 + cats 143 + amount 44 + note 44 + acct 43 + pad 213 + padding
   ≈ **621px**，而 600 高视口的 `92vh` = 552px → 差 32px，必须自己滑。
   逐段压：分类图标 42→36、键盘行 48→44、金额字号 38→34、
   `.led-field` 内边距 `11px 14px`→`8px 12px`、头部 34→32、各处 margin 6→4 …
   → **535px**。
2. **`vh` 在手机上量的是「大视口」。** 它是按**地址栏隐藏后**的高度算的，
   地址栏一露出来真实可视区就小于 `92vh`，浮层顶被顶出屏幕外 ——
   这不是「高度没调够」，是**尺子错了**（MEMORY.md 红线 39）。

```css
max-height: 92vh;    /* 旧值留着 —— 不认识 dvh 的浏览器在解析期就丢掉 */
max-height: 92dvh;   /* 新的在后 */
```

**验收标准（别只在最高那档量一次）：** `verify_ledger_account.mjs` 第 7b 组
从「矮屏下滚到底够得着保存键」改成 **「浮层要装得下（不用用户自己滑）」** ——
`measureFit()` + `FIT_VIEWPORTS = [915, 873, 740, 667, 640, 600]` 六档，
每档断言 `scrollable === 0` **且**保存键在可视带内；另补一条横屏 720×360

## 六、近 6 个月趋势曲线图（v1.13.5 第二轮，用户 2026-09-23 第 3 条）

**零依赖手写 SVG**（红线 1 不许引图表库）。

`mount()` 会先清空容器，所以切换方向直接重挂即可）：

```
  .led-trend__readout   「9月 · 支出 ¥2,400.00」
  .led-trend__plot      ← SVG
  .led-trend__axis      首尾两个月标签
```

SVG：`viewBox="0 0 320 112"`，`padL/R 8`、`padT 14`、`padB 10`
（绘图带 **y ∈ [14, 102]**，`baseY = 102`）；
**3 条**网格线在 `[0, 1/2, 1]`（顶线正好压在峰值上、中线在正中、底线是基线 ——
跟参考图一致，别改回四等分）；渐变填充 `linearGradient#ledTrendFill`
（`var(--c-primary)` 从 `.22` 到 `0`）；`line` 是主色蓝 `stroke-width: 2.2`；
峰值处一个**空心圆环** + 一条**虚线垂线**；`allZero` 时圆环与垂线都不画。

### 🔴 控制点必须夹住

**Catmull-Rom → 三次贝塞尔**平滑：

```
c1y = p1.y + (p2.y - p0.y) / 6
c2y = p2.y - (p3.y - p1.y) / 6
```

这个插值**会过冲**：谷底沉到基线以下（看着像「负支出」）、峰顶拱出上边缘。
过冲量 ≈ **相邻落差 / 6**，所以只在「谷底离基线约 1/7 绘图高以内、两侧落差悬殊」
时才越界 —— 平时看不出来，一旦越界就是明显的视觉 bug。

```js
const clampY = (y) => Math.min(baseY, Math.max(padT, y));
```

实测（`viewBox 0 0 320 112`）：

| | 顶部 | 底部 |
|---|---|---|
| 不夹 | 13.7 | 104.8 |
| 夹住 | 14.0 | 100.6 |

阈值钉 **顶部 `>= 13.9` / 底部 `<= 101`**，两侧都能独立翻红。

🔴 **配套的负向验证必须有「够极端」的种子数据**（见 MEMORY.md 红线 40）：
第一版 `[820, 1460, 640, 1980, 910, 306.85]` 只拱 0.5px，
**把 `clampY` 整个删掉 71 条断言照样全绿** —— 假阳性。
换成 `[900, 2400, 120, 200, 1500, 600]` 才真顶出来。
⚠️ `addLedgerEntry` 拒 `amount <= 0`（「金额必须大于 0」），
**不能塞个 0 去人为制造贴基线谷底**，只能靠「陡而不为零」的数据。

### 其它要点

- **峰值取法 `if (v >= values[peak]) peak = i;`** —— 用 `>=` 不用 `>`，
  否则每个月都一样的平线会高亮**最旧**那个月，该高亮最近的。
- **`getBBox()`** 量真实绘制范围，比算术推算可靠（断言就靠它）。
- **`.led-trend__svg { height: auto; }`** —— 写死高度会把圆环**压成椭圆**。
- 空心圆环 = `fill: var(--c-surface); stroke: var(--c-primary)`。
- 颜色**全部走 CSS 变量**，JS 里不出现任何十六进制（红线 8）。
- ⚠️ **胶囊底色不能用 `--c-surface-2`**（#fafbfd）—— 它比白卡片还浅，
  会渲染成一块**看不见的白斑**（在流水列表分组标题上踩过同一个坑）。
  改用 `rgba(20, 30, 55, .055)`；选中项 `background: var(--c-text); color: var(--c-surface);`。
- 方向切换状态 `trendDir` 放在**模块作用域**，切页签再回来不重置。
- 按用户既有偏好（红线 18），曲线**只用主色蓝**，涨跌不染红绿。

标题副标题 / 支出收入两项 / 默认支出 / 读数 = `${labelOf(1)} · 支出 ¥2,400.00` /
轴首尾 / **3 条**网格线（且顶线 y 必须等于峰值圆环 y、中线在 58）/ 有渐变填充 /
**恰好 5 段三次贝塞尔**（是曲线不是折线）/
`getBBox()` 上下界 / 峰值顶到上边缘 / 空心圆环是主色描边 / 虚线垂线 /
**曲线是主色不是红绿**；再切到收入（`${labelOf(2)} · 收入 ¥800.00`，上下界重测）再切回。

### 退化数据（某一方向六个月全是 0）

⚠️ 上面那组种子**两个方向都有值**，永远走不到 `allZero` 分支 —— 守卫写了没人测。
真实场景很常见：只记过收入、从没记过支出的用户点开「支出」。补了一组只播 6 笔收入
（金额非零，确保是「真没支出」不是「空库」），断言：

- 趋势卡**照样渲染** —— 有流水就不该整块消失（`ov.entries.length` 是入口条件，
  不是「支出笔数」）
- 曲线**平躺在基线上**（实测顶 102 / 高 0，`baseY` 正是 102）
- **不画**圆环与垂线 —— 不然后果是一个孤零零的环贴在右下角，看着像「这个月有支出」
- 读数落在**最近**那个月（这是 `>=` 取并列最后一个的作用）· 支出 ¥0.00

已负向验证：去掉 `allZero` 守卫 → 恰好那 2 条红（平线本身仍绿）。

⚠️ **`scroll-behavior: smooth` 下别用坐标点击**（MEMORY.md 红线 41）：

## 七、流水列表：一天只有一组（v1.13.5 第三轮，用户 2026-09-23 第 4 条）

用户原话：「记账里面同一天的收入和支出放在一起啊」。

### 改前 / 改后

`buildEntryList()`（`web/js/screens/record/ledger_view.js`）原来按
**「日期 → 收支方向」两级**分组，一天里既有支出又有收入就 push 出**两个 `.led-day`**：

```
[ 09月19日 周六 | 支出 22.5 ]     ← 一个组
🍜 餐饮            -22.5
[ 09月19日 周六 | 收入 500 ]      ← 又一个组，日期胶囊几乎一样
💰 生活费          +500
```

同一天被拆成上下两块，扫起来像两天。现在**一天一个 `.led-day`**：

```
[ 09月19日 周六 | 支出 22.5 · 收入 500 ]
🍜 餐饮            -22.5
💰 生活费          +500
```

### 五个设计决定

| 决定 | 为什么 |
|---|---|
| 只有一边就**只报一边** | 不给另一边补「收入 0」。零值小计是纯噪音 —— 用户这天没记收入，不需要被告知 |
| `.led-day__head` 加 `flex-wrap: wrap` | 320px 机身 + 两组小计会顶到边界。实测 430px 宽下这一行 263px |
| 「支出 385」包成 `.led-day__sum` | `flex-wrap` 只会在 `.led-day__sum` 之间断行，不会把「支出」和「385」拆到两行 |
| 两组小计之间用 `::before` 画**圆点** | 再画一根竖线读起来像「换一段」，圆点读起来是「和」。挂在**第二个** sum 上，换行时不会孤零零留在上一行行尾 |
| 组内**不按方向二次排序** | 保持 `ov.entries` 的「日期倒序 + 同日内录入时间倒序」。流水是流水，录入先后本身就是信息；按方向重排会让这条线索消失 |

⚠️ 组头里小计的**标签顺序**仍固定「支出在前」（跟顶部方向切换、汇总卡一致）——
那只是标签顺序，**跟行的顺序是两回事**，别把两者混成一条规则去实现。

### 🔴 断言要用 `?.` 取值

`verify_ledger_list.mjs` 第 2 组里写的是 `day19.sums[1]?.total`，不是 `.sums[1].total`。
分组一旦回归，`sums[1]` 就是 `undefined`，**直接取属性会让整个脚本抛异常退出**，
后面几十条断言一条都不跑。负向验证时踩到：只报出 3 条红就崩了，看不到全貌；
改成 `?.` 之后同一场景完整报出 **8 条红**。
