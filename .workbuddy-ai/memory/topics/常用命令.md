## 服务

⚠️ 所有 `verify:*` 脚本都**要先起着 8080**，否则连接被拒。

## 测试

- `node tests/run_all.mjs` —— **11 套件**全跑。
- 单跑 E2E：`node tests/e2e_test.mjs`。
- 回归：`npm run verify:{week,glass,nav,backup,icons,assets,gestures,pwa,skip,ledgerform,ledgerlist,ledgeracct,transfer}`

⚠️ 三个容易踩的坑：

1. **别按 npm 脚本名猜文件名。** 对应关系是：
   - `verify:nav` → `tools/verify_nav_icon.mjs`（**不是** `verify:nav_icon`）
   - `verify:week` → `tools/verify_week_scroll.mjs`
   - `verify:ledgerlist` → `tools/verify_ledger_list.mjs`（**带下划线**）
   - `verify:ledgerform` → `tools/verify_ledger_form.mjs`

   自己写 `for` 循环批量跑时，猜错名字的那个脚本会**静默跳过**
   （MODULE_NOT_FOUND 被 `grep` 吃掉，输出里就少一行）——
   2026-09-23 我这么踩过一次，差点把「没跑」当成「跑过了」。
   **批量跑之前先 `ls tools/verify_*.mjs` 对一遍。**

2. `npm run --silent` 对**不存在**的脚本**静默无输出**，极易被误当成「跑过了」。

3. 一次 `for` 循环跑完全部会被 **120s 超时**打断；
   `skip` / `ledgeracct` 建议**单独跑**。

## 发布 / 出包

- PWA：`npm run pwa` / `npm run pwa:check`
- 安卓：`npm run android:sync` → `android:apk`（或 `android:apk:release`）
  - 工具链 `D:\android-toolchain`，**每次先 export `JAVA_HOME` 与 `ANDROID_HOME`**
  - ⚠️ `JAVA_HOME` 必须用 **Windows 反斜杠形式** `D:\android-toolchain\jdk-21.0.12.1+1`；
    `gradlew.bat` 不认 Git-Bash 的 `/d/...` 形式

## 图标

- 生成：`npm run icons`
- **校验：`npm run verify:icons`**（42 项，改图标后必跑）
- 肉眼复查：`node tools/zoom_icons.mjs` / `node tools/mask_preview.mjs`
