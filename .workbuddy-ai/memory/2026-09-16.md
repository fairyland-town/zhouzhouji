### 🔴 图标真 bug 一：圆角半径是猜的，把蓝色角啃掉了

`icon-512.png` 放大后四个圆角有**透明缺口**。
根因：`make_icons.mjs` 里硬编码 `ctx.roundRect(..., size * 0.225)`，
而这个 0.225 比源稿实际的圆角**小**，裁上去正好啃进蓝色。

**修法：从源图实测圆角半径，不要硬编码。**
在 `x = minX` 那一列自上而下找「蓝第一个出现的位置」，
与 `y = minY` 那一行自左向右找的起点相减，就是圆角的横向进深；
实测本稿 **294px，占内容边长 25.9%**（夹在 20%~30% 之间兜底）。

另外内容边界**必须外扩**（`pad = side * 0.022`）：
`isContent` 探的是「第一个明显不白的像素」，而 3D 稿边缘是「白→蓝」柔和渐变
外加一圈浅投影，所以探到的边界落在真实边缘**内侧**，
不外扩的话缩下去外缘会被削掉一圈。

### 🔴 图标真 bug 二：maskable 怎么贴都会带白角

源图是「圆角蓝方块 + 白底」，**外接方框的四个角是白的**。于是：

| 尝试 | 结果 |
| --- | --- |
| 缩小贴一份到安全区 | 白色**描边环**（白底跟着进来了） |
| 铺满贴 + 内容按内容框贴 | 白色**方块**（内容框的角也是白的） |
| **只贴一次 + 用作品自身的蓝铺底** | ✅ 正确 |

第三种做法：先 `fillRect` 铺满（蓝取自作品上边缘中点往下 12% 处，避开圆角与图案），
再把作品**圆角裁切后**贴到安全区中央。接缝不可见，四角不透明。

### 🔴 图标真 bug 三（做遮罩模拟才发现）：普通版会被圆形遮罩切掉内容

`tools/mask_preview.mjs`（新增）把图标套上圆形/超椭圆/圆角方遮罩渲染，
发现**普通版 512 在圆形遮罩下，日历左右两侧的活页环和右下钱包被切掉** ——
因为它贴边画满整个画布。有些启动器会对任何图标套圆遮罩。
修法：普通版留 **4% 内边距**，既能保住内容，视觉上仍是满格。

> 教训：maskable 正常**不代表**普通版安全。两者的暴露面不同，
> 必须**分别**套真实遮罩看一遍。

## 续六：v1.9.0 实现（月扣款时序 + 账户消费不进总账）

用户两条需求：

> 「1.月扣款的时候不是设置了立即扣除，而是在固定的设置的那一天扣款，要是设置日期在
> 扣款之前，到扣款日期就扣，要是设置日期在扣款之前，那么就不管他，下个月扣款日再扣。
> 2.避免重复计算，然后账户里面的消费不用走记账总账，只有充值的时候会记录在记账总账」

（第 1 条第二处「扣款之前」按用户澄清的口径读作「扣款**之后**」。）

### 需求 1：月扣款时序

**规则**：设置当时永不扣款；设置日**早于/等于**扣款日 → 本月照扣；
设置日**晚于**扣款日 → 本月不扣（该期作废），下月那天再扣。
错过的月份**全部补上、不设上限**（用户确认：「房租本来就是要交的」）。

**关键设计 —— 字段职责分离**（这是本轮唯一的真难点）：
- `lastRun` = **唯一权威**，表示「已执行到哪月」，`dueRecurring` 起点 = `lastRun + 1`
- `since` = 只负责「不许倒扣启用前的月份」；**重设时原地保留，不刷新**
- `sinceSkip` = 启用月那期是否已放弃（新增字段）
- `runCount` = **纯展示**「第 N 期 / 共 M 期」，**不参与任何判定**

`normalizeRecurring()` 给旧记录补 `runCount: 0` / `sinceSkip: false`。

### 🔴 写这个脚本踩的坑（两种方向的假阳性）

量「墨迹覆盖率」要把字形克隆进 canvas 数非透明像素，这里连踩两个坑：

1. **把根 `stroke` 抹成 `none`** → 描边图标量出 **0.0%**

白色镂空保留（它本来就该是空的）。

顺带一个教训：**阈值别拍脑袋写「×2」**。`stroke-width: 1.9` 在 24 viewBox
缩到 64px 本来就占 30% 以上，真实信号是「接近翻倍」。改成 `× 1.6`
并补一条「描边落在 30–45%」确认量的确实是线而不是块。

## 续八：v1.11.0 独立存储的安卓 App + 备份覆盖全部 7 张表

### 需求（用户原文）

> 我需要有独立储存的安卓软件app

追问后确定：**私有存储 + 自动备份到手机文件**；本轮**只把配置准备好**，
不下载 Android SDK、不构建。

### 🔴 挖出一个一直存在的丢数据 bug（本轮最大收获）

**导出 JSON 备份 → 再导入，活动全部消失，而且不报任何错。**

根因是字段命名不对称：

| 环节 | 字段名 |
| --- | --- |
| `Event` 构造函数 | `startTime`（camelCase） |
| `Event.toJSON()` 输出 | `start_time`（snake_case） |
| `bulkAdd()` 导入 | `new Event(item)` ← 直接吃 snake_case |

`startTime` 变空串 → `validate()` 失败 → 记录被静默 `continue` 跳过。
**v1.10.0 及更早版本一直如此。** 修法：`bulkAdd()` 改用 `Event.fromRecord(item)`。

> 教训：**「导出用 A 名字、导入用 B 名字」这种不对称，必须有往返测试守着。**
> 没有 `verify_backup.mjs` 第 2 组，这个 bug 会一直藏着 —— 错误是静默的。

### 备份从 1 张表扩到 7 张表

`version: 2`：events 走 `toJSON()`（不含 id），其余 6 表存**原始记录（含 id）**。

**为什么其余 6 个不能也走 `toJSON()`**：`ledger.accountId → accounts.id`、
`checkin_logs.checkin_id → checkins.id` 都是**真外键**，而 `Account.toJSON()`
是**故意不含 id** 的（那是给「导入单个账户」用的），拿它做备份关联会全断。

导入：合并 / 替换两种模式（`actionSheet` 选，不默认替换）；
**整数 id 全部重分配 + 外键同步改写**；`accounts.entries[].id` 是全局唯一字符串，原样保留；
孤儿记录丢弃；兼容裸数组 / v1 / v2 三种历史格式。

### 零构建 → 只能用 `nativePromise`

项目没有打包器，`import '@capacitor/filesystem'` 这种裸模块名解析不了。
**不走插件 npm JS，改走 Capacitor 注入 WebView 的低层通道**：

```js
window.Capacitor.nativePromise('Filesystem', 'writeFile', { ... })
```

→ 不需要打包器、不需要 import map、不往 `web/` 里塞插件 JS，与零依赖原则一致。
封装在 `native_bridge.js`（`isNative()` / `callNative()`），**浏览器里全部 no-op**。

### 构建链路两个硬事实

1. **需要 JDK 21，不是 17** —— `JavaVersion.VERSION_21` 硬编码在两个 `build.gradle` 里。
2. **`google()` 仓库本机不可达**（`maven.google.com` 超时）——
   已在 4 个位置换成 `https://dl.google.com/dl/android/maven2` + 阿里云镜像。
   ⚠️ **`npx cap add android` 会覆盖这些改动。**
