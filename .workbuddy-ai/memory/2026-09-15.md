## 名称解析缺陷修复（用户第二轮反馈）

用户截图反馈：泰康保险集团的宣讲会通知，名称只识别出「科技专场」，
企业名、届次、活动类型、地点后缀全丢。

原始通知：
```
~~泰康保险集团2027"科技专场"巡回宣讲会——西南财经大学站~~
现场面试！！！现场发offer！！！
时间：9月17日下午15:00
地点：柳林校区弘远楼101
```

### 根因（两个叠加）
1. 引号规则（TITLE_QUOTED）优先级高于整行规则，把 `"科技专场"` 当成整个名称
2. 未处理微信/公众号常见的 Markdown `~~波浪线~~` 强调标记

### 修复要点
- 新增 `looksLikeFullTitle()`：若某行含明确活动类型词（宣讲会/报告会/讲座/会议/
  论坛/双选会/招聘会/专场/分享会/说明会…）且不含句子标点（。；），则整行即活动名，
  **优先于**行内引号片段。引号规则降为兜底。
- cleanTitle 增强：去 `~~`/`**`/`__`；**先整体剥离成对栏目标签**（【宣讲会】）再清理残留符号
- 这条顺序很关键：先去掉单个 `【` 会导致成对规则失配，残留 `】`

### 附带修正
原来断言「关于举办学术报告会的通知」→「学术报告会」是错的。
去掉「关于举办」后，长标题会退化成无意义的「宣讲会」；保留反而更好。
已改为保留，并补充说明。

### 四个真实缺陷（都有回归测试）

1. **职称后缀剥离顺序错**：「李敏副教授」→「李敏副」。

2. **强词压过强词**：「就业专题讲座」被判招聘。
   修法：强关键词层保持权威，只有**泛学术容器词**才允许被更明确的非学术信号压过。
3. **裸容器词误判学术**：「新能源材料发展论坛」→ 学术会议。
   修法：定义 GENERIC_ACADEMIC_WORDS（论坛/年会/研讨会/交流会/workshop…），

4. **CSS 自定义属性静默失效**：卡片 `--cat` 恒为回退值，分类配色完全不生效。

   而 `style` 只认驼峰属性名，`--cat` 这类自定义属性必须走 `el.style.setProperty()`。
   已新增 `applyStyle()` 辅助函数。**这个坑很隐蔽，因为在浏览器里不报错，只是静默丢弃。**

## 缺陷修复 —— 确认页不能上下滚动 / 无法保存（用户实测反馈）

用户截图反馈「确认活动信息」页面不能上下移动、也无法保存，页面底部（地点输入框、
确认添加按钮）被裁掉点不到。

### 根因
**`.screen` 这个类被 6 个屏幕的根节点使用（`h('div', {class:'screen screen--xxx'})`），
但 style.css 里从未定义过它。** grep `\.screen` 零匹配。

后果：`.screen` 落回默认 `display:block`、无 flex、无高度约束。它内部的 `.app-body`
虽然写了 `flex:1; overflow-y:auto`，但父级不是 flex 容器、也没有确定高度，
`flex:1` 完全无效，`.app-body` 按内容自然高度撑开 → 超出 `#phone` 的 844px →
被 `#phone { overflow:hidden }` 直接裁掉，既不滚动也不显示。

### 修复
`web/css/style.css` 在 `#app` 规则之后补上（这段原来完全缺失）：
```css
.screen {
  flex: 1;
  display: flex;
  flex-direction: column;
  overflow: hidden;
  min-height: 0;   /* 关键：flex 子项默认 min-height:auto 会按内容撑开而不收缩 */
  width: 100%;
}
```
打通了完整纵向 flex 链：`#phone → #app → #screen-slot → .screen → .app-body`。

### 回归固化
E2E 新增第 12 组「布局与滚动链路」，5 项断言：
`.screen` flexGrow=1、`.screen` 高度不超出 slot、`.app-body` overflow 为 auto、
真实滚动 `scrollTop` 增大、滚到底后「确认添加」按钮 rect 落在 `#screen-slot` 可视区内、
点击后活动真的写库。E2E 75 → 84 项，全套 394 → 403 项全部通过。

### 教训（第三次同类）
**「用了但没定义的类名」是布局类 bug 的头号来源。** 页面能渲染、不报错、
部分内容正常，只有滚动/裁切出问题 —— 因为缺的往往不是某个具体属性，
而是整条 flex 链中的一环。排查顺序应当是：
从滚动容器（`.app-body`）往上逐级检查每个祖先的 `display` / `flex` / `min-height` / `overflow`，
而不是只看滚动容器自己。这类问题无法靠单元测试发现，必须在 E2E 里
**用 `getBoundingClientRect()` 断言元素真的落在可视区内 + 真的能滚动**。

1. **题目被解析成「活动签到」** —— 句子内嵌规则的动词表里带了 `进行`，

3. **`报告人：John F. Nash 教授` 仍提取不到** —— `cleanName()` 在**剥中文职称后缀之前**

   → `JohnF.Nash教授` → 校验失败。`Harry Zhang` 之所以能过，只是因为它的正则已经剥掉了职称。
   → 改为**探针式先剥职称再判 ASCII**；英文分支末尾再剥一次职称。

# v1.3.2 —— 记账备注：抓出「这笔钱干什么用了」（用户反馈）

## 需求
用户：「在记账的时候识别只识别出在哪一大类，并没有识别出和抓取储存我这一笔钱是干什么了」。
即分类有了，但**备注空**——用户要的是「买的是什么」，不只是一个粗类目。

## 根因
`parseReceipt()` 里 `note = parseMerchant()`，而 `parseMerchant()` **只认 8 个硬编码标签**
（收款方/收款人/商户/商家…）。真实输入大量无标签：
- 支付宝账单页把店名**独立成行**（「…¥28.00 / 2026-09-15 / 星际烤肉店 / 订单号…」）
- 一句话记账「午饭 12.5 元」——根本没人去提「午饭」
→ 备注全空。

## 修复
新增 `parseNote()` **三级策略**：
1. 带标签（收款方/商家…）→ 取标签后的值
2. **独立成行的店名** → 逐行排除金额/日期/App 名/状态词/「标签：值」行，剩下的中文短行即店名
3. **一句话剥短语** → 新增 `extractPhrase()` 逐层剥掉：
   货币金额 → 日期时间 → 方向/动作词 → 时间前缀 → 裸数字 → 标点 → App 名/状态词
   （顺序很重要：先剥带单位的金额，再剥裸数字，否则「12.5」会被当普通数字提前清掉）

修复过程中又抓到 1 个衍生缺陷：**「支付成功」被算成有效备注，剥完残留孤立的「成功」**。
→ ① 整串状态短语先删（`支付成功`），单词后删；② 追加残渣正则清「成功/完成/失败/进行中」；
  ③ `isMeaningfulNote()` 用 `NOTE_RESIDUE` 拒绝纯状态残渣。

## 顺带修的
- **备注空时 UI 静默留空 → 改为显式提示**「没读出这笔钱花在哪，建议补备注」。
  原来的提示语说「已识别，请核对金额与分类」，会让用户以为识别完整了。
- 餐饮关键词补入 `烤肉/夜宵/小吃/面馆/米线/汉堡/披萨/必胜客`——
  否则「星际烤肉店」这种街边小店名既抓不到备注、又掉进「其他支出」，双失准。

## 教训（写进 MEMORY.md 了）
- **识别「哪一类」和识别「是什么」是两件事，不能让一个字段的解析器兼任。**
  分类是**归类**（命中关键词即可），备注是**抽取**（要从噪声里剥出剩余信息）。
  共用一套正则时，抽取方必然被归类方的窄标签集限制住。
- **「有值」不等于「有意义」。** `支付成功` 剥掉「支付」后的「成功」在字符串层面有效、
  语义层面是残渣。凡「从文本剥信息」都要加一条「剥完剩下的还成立吗」的判据。

## 测试
594 → **613 项全部通过**
（单元 108 / 分类 104 / 语料 130 / 记录 114→127 / OCR 12 / E2E 126→132）。
新增 11 条备注解析用例 + 6 条端到端断言（含「无用途时提示补备注」）。
文件：`web/js/services/receipt_parser.js`（主要）、`web/js/screens/record/ledger_view.js`（提示语）。

# v1.4.1 修记账金额识别（型号混入 + OCR 行序）

## 用户反馈原文
> 1. 记录里面的识别有问题，识别的是第一次出现的数字，但是我第一次出现的要是买商品的型号，
>    那么价格显示的也是型号而不是价格
> 2. 会出现图片的情况把早餐金额什么的都显示在前面了

## 根因（两个独立缺陷，不是「取了第一个数字」）
1. **型号被当金额** —— 通用正则 `\d{1,9}(?:[.,]\d{1,2})?` 会从 `g27` / `iPhone15`
   里抠出 `27` / `15`；旧的兜底策略又是「全文取最大」，型号照样参与竞争。
2. **行序决定结果** —— 旧 `parseAmount` 的策略 ②（同行）与 ④（兜底）都用
   `Math.max(...)` 扫全文。OCR 行序不稳定，某个小额数字只要被 `¥`/`元` 标记「强化」，
   就会压过真正的金额。
> 认知修正：问题不是「取第一个」，而是「**没有货币记号的数字和真金额平权竞争**」。

## 修法（web/js/services/receipt_parser.js）
- 新增 `isAmountLike(num, s, i)` 守卫链：左侧紧贴拉丁字母 → 否；千分位分组 / ≥7 位 → 否；
  4 位整数紧跟 `年月日期届号` → 否；数字后紧跟中文量词 → 否。
- 新增 `collectAmounts()`：逐行收集候选并标注 `strong`（该行带货币记号）。
  **解析前先把 `9月15日` / `14:32` 整段替换掉**，避免拆出 9、15 参赛。
- `parseAmount` 新策略链：① 金额关键词同行 → ② strong 候选取最大（**行序无关**）
  → ③ 带正负号独占一行 → ④ `trailingPriceOnLine` 行尾唯一数字（一句话兜底）
  → ⑤ 纯数字独占一行（OCR 丢小数点）→ ⑥ 兜底。
- 新增 `trailingPriceOnLine()`：**不能复用 isAmountLike** —— isAmountLike 的定位是
  「有货币记号的强候选」，会把 `午饭100` 的 100 也滤掉。这里只排型号/卡号/年份/量词。
- `NOISE_LINES` 增补：`/银行/`、`储蓄卡|信用卡`、`持卡人|开户行`、`身份证`、
  `商户单号`、`券码|券号|核销码`。

## 调试踩坑（本轮最大教训）

**括号配平靠"数数"会把人带偏，浪费了好几轮。**

`account_view.js` 报 `Unexpected reserved word`。我写了三个脚本去查配平
（正则 strip / tokenizer 扫 / 括号计数），**全部说"平衡"**，于是完全走错方向。

真相有两条，都很朴素：
1. **括号数平衡 ≠ 语法正确**。`h('div', {...}, [...])` 少写一个 `[`，
   或 `])` 写成 `]))`，数量可以刚好抵消。配平脚本永远查不出来。
2. **报错行是症状不是病灶**。Node 报最后一行 `await render()`，
   真正原因是 **`AccountView` 忘了写 `async`**。

正确顺序应该是：`node --check` 拿报错行 → **直接读那个函数附近的源码**（肉眼比脚本快）
→ 只在确实需要时才写辅助脚本。

另外还踩了：`stats.count` 想当然当成"活跃数"（实现里是"全部账户数"）、
`$$eval(...)[0]` 拿不到值（该用 `$eval`）、
CSS 写了不存在的令牌 `--c-text-1` / `--c-fill` / `--r-lg`
（实际是 `--c-text` / `--c-surface-2` / `--radius-lg`，**样式静默失效不报错**）。

### 本轮踩的坑（都很典型）

1. **flex 负 margin 被剩余空间计算吃掉** 🔴 最值得记
   `.bottom-nav__fab` 要「跨出 dock 上沿」，
   用 `align-self: center` + `margin-top: -24px`，实测只上浮 **9px** 而非 24px。
   原因：flex 分配剩余空间时**把 margin 一起算进去了**。
   **改用 `align-self: flex-start`**，位移量才等于 margin 本身 →
   dock 66 / 按钮 58 / `margin-top: -20px` → 实测跨出 19px。
   教训：**flex 里用负 margin 做位移时，不要配 `align-self: center`。**

2. **UI 加动效会大面积打挂 E2E 的 click** 🔴
   一次改了 6 处点击失败，报错统一是
   `Node is either not clickable or not an Element`。

   再开新的，并改用 `[data-quick="paste"]` 属性选择器 + `$eval(el => el.click())`
   （绕开坐标计算，比 `.click()` 稳）。

4. **`serve.mjs` 读的是 argv[3] 不是 argv[2]**
   写成 `serve.mjs local` 会把 `'local'` 当端口 → `ERR_SOCKET_BAD_PORT`。
   想只监听本机要写全：`node tools/serve.mjs 8080 local`。

5. **`.acct-intro` 原本是虚线框**，在玻璃体系里显得"未完成/临时"，
   改成中性玻璃卡。**玻璃体系下要重新审视所有"特殊样式"是否还成立。**

6. **纯色背景让 `backdrop-filter` 看起来像没生效** 🔴
   玻璃必须有东西可模糊。给 `body` 和 `#phone` 都加了三处径向光晕
   （`--bg-glow-a/b/c`），玻璃的层次感才显出来。

## v1.7.0：总账同步 · 滚动修复 · 每月扣款 · Tab 换位

### 需求（用户原文）

> 1.代办和记账换一个位置。2，账户里面的金额充值没有同步到消费记录里面去，我想要的是，我往卡里冲了多少钱那么账单显示我这一笔钱花了多少钱往哪里冲（意思越是记账的账单是所有的消费金额）3.账户界面不能上下滑动，比如多个账户的同时，会导致只能看见第一账户不能看到其他的账户，4，账户里面每一个账户的多一个功能就是可以每个月按时扣款（这个选择性设置）

四项，其中 2、3 是用户实际踩到的 bug。**没有新增任何依赖，DB_VERSION 仍是 4，仍是 7 个存储。**

### 一、第 3 项：用「对比四个子视图」定位滚动断链

用户描述是「多账户只能看到第一个」，容易误判成「内容太长挤出去」。
实际对比类名就找到了：

```
checkin_view.js:23   class: 'app-body'    ✅
ledger_view.js:37    class: 'app-body'    ✅
todo_view.js:32      class: 'app-body'    ✅
account_view.js:45   class: 'acct-view'   ❌ 唯一例外
```

而 CSS 只给 `.app-body` 补 `flex:1`。所以 `.acct-view` 既没撑满也没滚动，
内容被宿主 `.record-body-host` 的 `overflow:hidden` 裁掉。

**修复选择**：没有改类名为 `app-body acct-view`（会连带套上 `.app-body` 的
padding / scroll-behavior / 滚动条等规则，副作用不可控），
而是在 CSS 里精确补 `.record-body-host > .acct-view`，
只复制它真正需要的属性，留白取值与 `.app-body` 对齐。

### 二、第 2 项：镜像设计

用户那句「记账的账单是所有的消费金额」是关键 —— 他要的不是「多一个功能」，
而是**记账页的语义变了：从"我手动记的几笔"变成"我全部的钱的进出"**。

- 新增 `acct_in` / `acct_out` 两个**系统分类**（`system: true`）。
  **不复用「其他收入/支出」**：账户充值只是钱从口袋 A 挪到口袋 B，
  不是真实收入，混进「其他收入」会让月度统计失真。
- `ledgerCategoriesOf()` 过滤掉系统分类 → 「记一笔」里选不到，否则用户手动也能选「账户充值」。
- `(account_id, account_entry_id)` 做去重键。
- **三处级联**：删流水 / 删账户 / 记账页只读。
- 镜像失败只 `console.warn`，**不回滚账户流水**。

### 三、第 4 项：四个设计决策

1. **日期限制 1–28**，不做到 31 + 月末兜底。29–31 在有的月份不存在，
   允许填就必须定义「2 月怎么算」，无论跳 3 月还是落 2 月末都是隐式行为，用户难预期。
2. **加 `since`（生效月份）字段**。最初只看 `lastRun`，结果新建账户 `lastRun=null`
   时向前回溯 24 个月 → **一次产生 24 笔待扣款**（测试直接抓到，期望 1 实际 24）。修掉。
3. **`amount > 0` 才算真正启用**，否则 UI 会显示「每月扣 ¥0.00」这种荒谬承诺。
4. **旧数据优雅兜底**：v1.6 的账户没有该字段，`normalizeRecurring()` 对
   null / 非对象 / 缺字段全部回落「未启用」，专门写了 5 条测试覆盖。

### 四、本轮踩的坑（7 个）

| # | 现象 | 根因 | 修法 |

| 1 | E2E 报 `formatDate is not defined` | `setRecurring` 用了但 `account_service.js` 没导入 | 补 import |

### 图标为什么重画

旧图标是**手描 16×16 点阵的「周」字**，在 512px 下笔画是台阶状的方块，很粗糙。
「周」字本身也无法传达「按周归类活动」这层语义。

### 关键实现：从「点阵」改为「有符号距离场（SDF）」

`tools/make_icons.mjs` 重写。**不再超级采样，也不引任何依赖**：
每个形状用 `sdRoundRect` / `sdCircle` / `sdRoundRectStroke` 求「点到形状的有符号距离」，
再用 `coverage(d) = clamp(0.5 - d/aa)` 换算覆盖率 → 边缘天然抗锯齿。
好处是**一份几何在 180/192/512 下完全等比**，不会各写一套常数。

踩的坑（值得记）：
1. **活页环一开始写成「顶部两个小耳朵」** —— 因为把环的长度算式
   写成 `ringY - (calCY - calHH) + strokeW/2`，算出来是负数长度，缩成小凸起，
   看起来像个卡通脑袋。**改成用「两个端点 + 中点/半长」明确定义胶囊**才修好。
2. **描边要用 `sdRoundRectStroke`**（先内缩 `strokeW/2` 求圆角矩形距离，再减 `strokeW/2`），
   而不是「大矩形减小矩形」—— 后者在圆角处会产生月牙缺口。
3. **表头分隔线最初贴到日历上沿**，看起来被压扁；挪到上沿往下 28% 才透气。

- `css/style.css` —— 新增 `.modal__hint`（危险色提示）。
- `guide_screen.js` —— 「② 记账」补一句：充值要填来源且不能跳过。

### 关键设计判断

**为什么不把必填逻辑写在调用处。**
`promptDialog` 的 `read()` 是 `input.value.trim() || null`，
所以「空内容提交」和「点取消」返回的都是 `null`，调用处分不清。
若只写 `if (!note) return`，用户会遇到「点了保存什么都没发生」的静默失败。
所以做进弹窗内部：**不关窗 + 就地红字提示 + 一输入即消失**，
这样调用处拿到的 `null` 永远只代表「用户主动取消」，语义干净。

### 踩的坑

1. **`verify_*.mjs` 报 `Cannot find package 'puppeteer-core'`** ——
   ESM 不认 `NODE_PATH`。照抄 `verify_glass.mjs` 开头的
   `existsSync` 探测 + `pathToFileURL()` 动态 import 就好了。
2. **`DatabaseService.init is not a function`** —— `database_service.js` 导出的是**对象**
   且没有 `init`。正确写法是在页面里 `await import('/js/services/account_service.js')`
   取 `.default`（注意是**网页根路径**，不是相对 `tools/` 的路径），
   `AccountService.create()` 内部会自行初始化数据库。
